# P2_03: 요미의 방 탑다운 상호작용형 허브 기획 초안

## 1. 문서 목적

기존 `YomiRoomScene`의 버튼 중심 메뉴를 탑다운 쯔꾸르형 공간으로 개편한다. 플레이어는 요미를 직접 움직여 방 안을 탐색하고, 가구와 생활용품에 접근해 기존의 자유 대화, 휴식, 트레이딩, 외출 기능을 실행한다.

본 문서는 아트 제작과 프로그래밍 착수 전 단계의 MVP 기획 초안이다. 기존 Phase 2의 시간·체력·LLM·씬 전환 로직은 유지하고, 기능을 호출하는 입력 방식만 버튼에서 공간 상호작용으로 교체하는 것을 원칙으로 한다.

---

## 2. 핵심 콘셉트

- **장르 표현:** 탑다운 2D 생활 공간 탐색 + 미연시 허브
- **플레이 캐릭터:** 요미
- **핵심 경험:** 방을 직접 걸어 다니며 다음 행동을 선택하는 일상성
- **시간 진행:** 실시간으로 흐르지 않고, 상호작용이 확정될 때만 타임 슬롯 소모
- **기존 기능 보존:** `YomiRoomManager`, `DatingTimeManager`, `DatingSimLLMController`, `LoadingScreenController` 재사용
- **목표 플레이 시간:** 다음 행동 선택까지 약 5~20초

### 기본 플레이 루프

```text
YomiRoomScene 진입
  → 방 내부 탐색
  → 상호작용 오브젝트 접근
  → 안내 표시 및 상호작용 입력
  → 행동 설명/비용 확인
  → 행동 실행
  → 방 내부 결과 연출 또는 다른 씬으로 전환
```

## 3. 기존 방 이미지 활용 방안

### 참조 에셋

- 야간 원본: `Assets/Img/Background.png`
- 아침 원본: `Assets/Resources/Backgrounds/RoomMorning.png`
- 저녁 원본: `Assets/Resources/Backgrounds/RoomSunset.png`
- 원본 해상도: 1672×941, 16:9

### 활용 원칙

현재 이미지는 정면 원근이 적용된 일러스트이므로 충돌과 이동이 필요한 탑다운 맵에 그대로 사용할 수 없다. 다음 요소를 추출하여 **탑다운 전용 맵을 새로 제작하는 시각 레퍼런스**로 사용한다.

- 방의 주조색과 시간대별 조명
- 벽, 바닥, 창문 및 도시 야경 분위기
- PC 책상, 침대, 문, 소형 가구의 디자인 언어
- 사이버펑크와 생활감이 섞인 요미 방의 정체성

원본 이미지를 단순 회전하거나 원근 변형해 바닥으로 사용하는 방식은 금지한다. 탑다운 시점에서 읽히는 바닥, 벽, 가구 상판과 측면을 별도 레이어 또는 타일로 재구성한다.

### 시간대 표현

- **아침:** 푸른 자연광, 밝은 바닥과 창가
- **저녁:** 주황빛 역광과 도시 노을
- **야간:** 모니터 및 네온 조명이 강조된 청색 계열
- 기존 `DayTimeBackgroundController`의 시간 판정 개념을 재사용하되, 탑다운 맵에서는 배경 교체보다 전역 색조와 조명 오버레이 교체를 우선한다.

## 4. 맵 구성 초안

### 권장 공간 배치

```text
┌──────────────────────────────────────┐
│  창문 / 도시 배경                    │
│                                      │
│  [침대]                [PC 책상]     │
│   휴식                  트레이딩      │
│                                      │
│          이동 가능 중심 공간         │
│                                      │
│  [폰 충전대]            [외출 통로]  │
│   자유대화              접촉 시 외출 │
└──────────────────────────────────────┘
```

### 레이어 구조

1. `Floor`: 이동 가능한 바닥
2. `Walls`: 벽과 방 외곽 충돌
3. `FurnitureBack`: 캐릭터 뒤에 보이는 가구
4. `Player`: 요미 캐릭터
5. `FurnitureFront`: 캐릭터 앞을 가리는 가구 전면
6. `InteractionMarkers`: 상호작용 감지 영역
7. `Lighting`: 시간대 색조 및 창문 광원
8. `HUD`: 체력, 타임 슬롯, 호감도, 집착도
9. `InteractionUI`: 안내 문구, 확인 패널, 대화 UI

### 이동 영역 원칙

- 가구 사이 통로는 캐릭터 폭의 최소 1.5배를 확보한다.
- 핵심 오브젝트 앞에는 캐릭터 1명이 정지할 수 있는 상호작용 지점을 둔다.
- 문이나 가구 뒤에 캐릭터가 끼이지 않도록 충돌체는 시각적 외곽보다 단순하게 구성한다.
- 화면 가장자리와 상단 HUD 아래에는 안전 여백을 둔다.

## 5. 핵심 상호작용 오브젝트

| 오브젝트 | 기능 | 기존 호출 대상 | 기본 비용 | 처리 방식 |
|---|---|---|---|---|
| PC | 트레이딩 시작 | `YomiRoomManager.StartTrading()` | 없음 | 확인 후 `LoadingScene`을 거쳐 `GameScene` 진입 |
| 침대 | 휴식 | `YomiRoomManager.TryRest()` | 타임 슬롯 1 | 체력 10 회복 후 방 안에서 짧은 연출 |
| 스마트폰 | 자유 대화 | `YomiRoomManager.TryStartFreeChat()` | 타임 슬롯 1 | LLM 대화 UI를 방 위에 오버레이로 표시 |
| 배경 하단 외출 통로 | 외출 | `YomiRoomManager.MoveToWorldMap()` | 이동 자체는 없음 | 통로 끝 트리거 접촉 시 `WorldMapScene` 진입 |

### PC: 트레이딩

- 모니터 앞 상호작용 지점에서 입력하면 `PC를 켜고 트레이딩을 시작할까요?` 확인 패널을 표시한다.
- 확인 시 캐릭터가 의자를 바라보는 짧은 동작 후 트레이딩 씬으로 이동한다.
- 취소 시 탐색 상태로 즉시 복귀한다.

### 침대: 휴식

- 침대 옆 상호작용 지점에서 현재 체력과 회복량, 소모 슬롯을 표시한다.
- 확인 시 기존 `TryRest()`를 호출한다.
- 화면 암전 또는 이불 흔들림 등 1~2초의 간단한 연출 후 HUD를 갱신한다.
- 슬롯이 부족하면 행동을 실행하지 않고 부족 사유를 안내한다.

### 스마트폰: 자유 대화

- 스마트폰이 놓인 책상 또는 충전대를 조사해 자유 대화를 시작한다.
- 확인 시 기존 `TryStartFreeChat()`을 호출하고 `DatingSimLLMController` 기반 대화 패널을 연다.
- 대화 UI가 열린 동안 이동 입력을 잠근다.
- 대화 종료 후 플레이어를 탐색 상태로 되돌린다.

### 배경 하단 통로: 외출

- 별도의 문 스프라이트와 클릭 상호작용은 사용하지 않는다.
- 요미가 배경 하단의 외출 통로 끝에 닿으면 `MoveToWorldMap()`을 호출한다.
- 월드맵에서 방으로 돌아올 때는 외출 통로 안쪽 복귀 지점에 요미를 배치한다.

## 6. 플레이어 조작

### PC

- 이동: `WASD`
- 상호작용: 상호작용 범위 안에서 마우스 좌클릭
- 취소/패널 닫기: `Esc`

### 이동 감각

- 4방향 이동을 MVP 기준으로 사용한다.
- 대각 입력은 허용하되 애니메이션은 가장 우세한 축의 방향을 사용한다.
- 가속 없이 일정 속도로 이동하며, UI가 열리면 속도를 즉시 0으로 만든다.
- Rigidbody2D 기반 충돌을 사용하고 Z축 또는 Sorting Layer로 가구 앞뒤 관계를 표현한다.

## 7. 상호작용 UX

### 탐색 중 안내

- 감지 범위 진입 시 오브젝트 위 또는 화면 하단에 `E  상호작용`을 표시한다.
- 여러 오브젝트가 겹치면 플레이어와 가장 가깝고 바라보는 방향에 있는 대상 하나만 선택한다.
- 현재 선택된 오브젝트에는 외곽선, 밝기 상승 또는 작은 아이콘으로 강조 효과를 준다.

### 행동 확인 패널

```text
[침대]
잠시 휴식할까요?
체력 +10 / 시간 슬롯 -1

[확인]  [취소]
```

- 자원 소모가 있는 행동은 실행 전에 비용과 결과를 반드시 표시한다.
- 실행 불가능한 경우 확인 버튼을 비활성화하고 부족한 자원을 붉은색으로 표시한다.
- 씬 전환 행동은 중복 입력을 막기 위해 확인 직후 전체 입력을 잠근다.

### 상단 HUD

- 체력, 타임 슬롯, 호감도, 집착도를 항상 표시한다.
- 기존 버튼 네 개는 제거하되, 키보드·모바일 조작 안내와 일시정지 버튼은 유지한다.
- HUD가 맵이나 캐릭터를 과도하게 가리지 않도록 화면 안전 영역을 적용한다.

## 8. 시간 및 상태 규칙

- 방과 월드맵에서는 트레이딩처럼 초 단위 시간이 흐르지 않는다.
- 이동과 오브젝트 조사만으로는 타임 슬롯을 소비하지 않는다.
- 행동을 확인하여 성공적으로 실행한 순간에만 슬롯과 체력을 변경한다.
- `DatingTimeManager`의 하루 기본 슬롯은 5를 유지한다.
- 슬롯이 0이 되었을 때 자동으로 날짜를 넘길지, 강제 취침을 유도할지는 별도 확정이 필요하다.
- 대화, 확인 패널, 휴식 연출 및 로딩 중에는 캐릭터 이동을 잠근다.

### 권장 추가 규칙

- 슬롯 0 상태에서는 PC와 현관문 사용 여부를 별도로 결정해야 한다.
- MVP에서는 트레이딩 진입과 방 복귀 자체에는 슬롯 비용을 부과하지 않는다.
- 날짜 전환은 침대의 `하루 마무리` 선택지로 명시적으로 실행하는 방식을 우선 검토한다.

## 9. 시스템 구조 초안

### 신규 컴포넌트

- `YomiTopDownController`
  - 이동 입력, 방향, 걷기 애니메이션, 입력 잠금 관리
- `YomiRoomInteractionScanner`
  - 주변 상호작용 대상 탐색 및 우선순위 결정
- `YomiRoomInteractable`
  - 오브젝트 이름, 안내 문구, 행동 종류, 상호작용 지점 보유
- `YomiRoomInteractionUI`
  - 입력 안내, 확인 패널, 실패 피드백 표시
- `YomiRoomCameraController`
  - 방 크기에 따른 고정 카메라 또는 제한된 추적 카메라 처리
- `YomiRoomLightingController`
  - 시간대별 색조와 조명 오버레이 적용

### 행동 타입

```csharp
public enum YomiRoomInteractionType
{
    TradingPC,
    RestBed,
    FreeChatPhone
}
```

`YomiRoomInteractable`은 행동 로직을 직접 구현하지 않고 타입과 표시 데이터만 제공한다. 실제 실행은 `YomiRoomManager`가 담당하여 기존 자원 검사와 씬 이동 규칙을 유지한다.

### 상태 확장 제안

```text
Exploring       방 탐색 가능
PromptOpen      확인 패널 표시, 이동 불가
FreeChatting    LLM 대화 중
Resting         휴식 연출 중
Transitioning   씬 이동 중
```

기존 `Idle`은 `Exploring` 역할로 대체하거나 의미를 확장한다.

## 10. 필요한 신규 아트 에셋

### 맵

- 탑다운 바닥 및 벽 타일
- 창문과 도시 배경
- PC 책상과 의자
- 침대와 침구
- 스마트폰 또는 충전대
- 배경 하단 외출 통로와 충돌 트리거
- 장식 가구 및 생활 소품
- 가구 전면 가림용 스프라이트
- 아침, 저녁, 야간 조명 오버레이

### 요미 캐릭터

- 기본 대기: 상·하·좌·우
- 걷기: 방향별 최소 4프레임 권장
- PC 사용, 침대 진입, 스마트폰 확인용 짧은 상호작용 포즈
- 기존 스킨 시스템을 탑다운 캐릭터에도 적용할지는 MVP 이후 별도 검토

### 제작 기준 제안

- 논리 타일 크기: 32×32 px
- 캐릭터 표시 크기: 약 32×48 px 또는 48×64 px
- Pixels Per Unit은 전체 탑다운 에셋에서 하나로 통일
- 필터 모드는 `Point`, 압축은 최소화
- 상호작용 소품은 실루엣만으로 기능을 구분할 수 있어야 한다.

정확한 타일과 캐릭터 크기는 첫 맵 목업에서 가독성을 확인한 뒤 확정한다.

## 13. 완료 조건

- 요미가 방 안에서 벽과 가구를 통과하지 않고 이동한다.
- 네 가지 핵심 오브젝트가 거리와 방향에 따라 정확히 선택된다.
- PC, 침대, 스마트폰, 현관문이 각각 기존 트레이딩, 휴식, 자유 대화, 외출 기능을 호출한다.
- 자원 부족 시 차감이나 상태 변경 없이 명확한 안내가 표시된다.
- 씬 전환 및 대화 중 중복 입력이 발생하지 않는다.
- 월드맵에서 복귀했을 때 문 앞에서 정상적으로 탐색을 재개한다.
- 주요 PC 화면비에서 HUD 및 상호작용 UI가 잘리지 않는다.

## 14. 확정이 필요한 기획 항목

- 슬롯이 0이 되었을 때 자동 취침 또는 수동 하루 종료 여부
- PC 트레이딩 진입에 타임 슬롯을 부과할지 여부
- 스마트폰 자유 대화의 종료 조건과 최대 대화 횟수
- 탑다운 요미에 보유 스킨을 실시간 반영할지 여부
- 한 화면 고정 카메라와 제한 추적 카메라 중 최종 방식
- 기존 방 이미지와 탑다운 맵 사이의 전환 연출 또는 시각적 연결 방식
