# FX Overdose - AI 활용 기술 문서

## 1. 개요
본 문서는 『FX Overdose』 프로젝트에서 활용된 인공지능(AI) 기술의 전반적인 내역을 정리한 문서입니다.
개발 및 기획 과정에서 사용된 **AI 코딩 어시스턴트(Antigravity IDE) 활용 내역**과, 게임 내 탑재된 **하이브리드 AI 시스템(On-device LLM)**, 그리고 아트 워크플로우에 활용된 기술 및 외부 에셋 출처를 모두 다룹니다.

---

## 2. 개발 및 기획 과정의 AI 활용 (Antigravity IDE)

본 프로젝트는 기획, 문서화, 그리고 폴더 및 코드 구조화 과정 전반에 걸쳐 Antigravity IDE(AI 코딩 어시스턴트)를 적극 도입하여 개발 생산성을 극대화했습니다.

### 2.1. AI 협업 및 기획 방식
* **탑다운(Top-down) 기반 문서화:** 기획자(사용자)가 큰 틀의 요구사항과 방향성을 프롬프트로 제시하면, AI가 기존 프로젝트 내의 컨텍스트(문서, 코드 등)를 분석하여 디테일한 문서 템플릿과 초안을 작성하는 방식으로 협업이 진행되었습니다.
* **산재된 데이터의 체계화:** 기획/개발 과정에서 파편화된 텍스트와 아이디어 파일들을 AI를 통해 목적에 따라 카테고리별(UI, System, Design, AI 등)로 분류하고 디렉토리 구조를 재편성하여 프로젝트 유지보수성을 크게 높였습니다.
* **자동화된 템플릿 구성:** 유저 매뉴얼, 기술 문서 등 규격화가 필요한 문서들은 AI에게 목적(대상 독자, 필수 포함 항목 등)을 전달하여 일관성 있는 마크다운(Markdown) 및 PDF 템플릿으로 빠르게 변환/작성하였습니다.

### 2.2. 개발자가 전달한 주요 프롬프트 및 지시 사항
실제 개발/기획 과정에서 Antigravity IDE와 상호작용하며 사용된 핵심 프롬프트 패턴은 다음과 같습니다.
1. **문서 분류 및 구조화 프롬프트:** 
   > "프로젝트 폴더 내 산재된 게임 기획 문서들을 UI, System, Game Design, General Documentation 등의 카테고리로 나누고 깔끔한 디렉토리 구조를 제안해 줘."
2. **템플릿 생성 프롬프트:**
   > "게임 소개, 조작법, 설치 방법 등이 포함된 플레이어용 게임 설명서(User Manual) PDF 템플릿 구조를 짜 줘."
3. **기술 문서 요약 프롬프트:**
   > "우리가 작업하며 Antigravity IDE를 사용한 방법들, 내가 전달했던 프롬프트들, 기획 방식들이 모두 들어간 종합적인 AI 활용 기술 문서 초안을 작성해 줘."

## 3. 게임 내 탑재 AI: 하이브리드 AI 아키텍처 (Hybrid AI System)

게임 내에서는 LLM의 환각(Hallucination) 현상을 방지하고 게임 퍼포먼스를 확보하기 위해, 게임 로직과 AI 생성 텍스트를 엄격히 분리한 하이브리드 구조를 채택했습니다. 게임 내에서 **LLM은 오직 '돌발 선택 이벤트'의 텍스트 생성에만 개입**합니다.

### 3.1. 로직과 텍스트의 분리 (Separation of Text and Logic)
* 매매 판단, 일반 대사 및 돌발 선택지의 기계적 결과(예: 롱 포지션 강제, 차트 빔 발생, 자산 변동 등)는 C# 기반의 룰베이스(Rule-based) State Machine으로 하드코딩되어 처리됩니다.
* LLM은 게임 내부 밸런스 수치나 게임 논리는 건드리지 못한 채, C#이 넘겨준 템플릿(상황)에 맞추어 **이벤트 뉴스 제목, 뉴스 내용, 3가지 선택지의 텍스트(제목 및 설명)**만을 지어냅니다.

### 3.2. 비동기 사전 호출 (Async Pre-fetching)
* 온디바이스 로컬 LLM의 추론 지연 시간(Latency)을 유저가 체감하지 못하도록, 돌발 이벤트 발생 예정 시간 10~20분 전(인게임 시간 기준)에 백그라운드 비동기 작업(코루틴)을 통해 미리 프롬프트를 전송합니다.
* 완성된 이벤트 텍스트는 사전에 캐싱(Caching)해 두어 이벤트 발생 즉시 화면에 띄웁니다.

### 3.3. 문법 제약 및 포맷 강제 (Grammar & JSON Schema)
* LLM이 반환하는 돌발 이벤트 데이터를 게임 엔진이 안전하게 파싱할 수 있도록 `llama.cpp` 기반 플러그인의 `Grammar` 기능을 활용합니다. 
* 이를 통해 포맷 붕괴 없이 100% 안전하고 정형화된 JSON 형태의 응답만을 강제로 출력하게 만듭니다.

### 3.4. 주인공 AI (요미) 제어 및 상태 연동
* 캐릭터 '요미'는 현재 자산, 멘탈, 실시간 수익률(ROE) 변수를 종합하여 4단계 감정 상태(절망, 불안, 평온, 환희)를 가지며, 이에 따라 스탠딩 일러스트 및 애니메이션이 동적으로 변화합니다.
* 하루 1~2회 등장하는 '일일 돌발 선택 이벤트' 시에는 온디바이스 LLM이 실시간 인게임 변수(차트 상황 등)를 바탕으로 새로운 이벤트 대화를 생성합니다.
* **안전망 (Safety Guard/Fallback):** 모델이 외국어(중국어/영어)를 출력하여 폰트가 깨지는 현상을 방지하기 위해 자체 한국어 검출기(`IsValidKoreanText`)를 도입했으며, 문제 발생 시 미리 준비된 더미(Dummy) 데이터로 교체하여 출력을 방어합니다.

## 4. 인게임 AI 대상 주요 프롬프트 및 지시 사항

### 4.1. LLM 시스템 및 컨텍스트 프롬프트
* **페르소나 부여 (System Prompt):**
  > "너는 극도의 감정 기복을 가진 천재 비트코인 멘헤라 트레이더다. 반말과 집착, 감정적인 어조를 사용한다."
* **언어 제약 (Constraint Prompt):**
  > "[IMPORTANT] 무조건 한국어(Korean)로만 응답하세요! 영어나 한자, 중국어를 사용하면 절대 안 됩니다."
* **실시간 상태 주입 (Context Injection):**
  게임 진행 중 아래와 같이 실시간 데이터가 JSON 형태로 조립되어 프롬프트에 주입됩니다.
  ```json
  {
    "balance": 12450.0,
    "roe_percentage": -42.5,
    "current_position": "Long (10x)",
    "mental_ratio": 0.18,
    "recent_event": "스탑로스 근처까지 가격 하락"
  }
  ```

### 4.2. 이미지 생성형 AI 프롬프트 (스프라이트 베리에이션)
* 기존 게임 스프라이트의 정체성(얼굴, 인체 비율)과 상태별 구도(Pose)를 완벽히 유지하면서 복장만을 교체하기 위해 엄격한 락(Lock) 프롬프트를 사용했습니다.
* **주요 명령어 예시:** 
  > `Use case: identity-preserve`, `Reproduce Image 2's exact pose, facial expression... Change only the outfit and hairstyle...`

## 5. 외부 에셋 / 오픈소스 출처

### 5.1. 대규모 언어 모델 (LLM) 및 관련 도구
* **적용 언어 모델:** `Llama-3.2-Korean-Bllossom-3B`
  * **출처:** [Bllossom (HuggingFace)](https://huggingface.co/Bllossom/llama-3.2-Korean-Bllossom-3B-gguf-Q4_K_M)
  * **특징:** 한국어 이해 및 역할극(Roleplay) 성능에 특화된 초경량 온디바이스 모델 
  * **포맷:** GGUF 포맷 (`Q4_K_M` INT4 양자화 적용, 약 2.2GB)
  * *(※ 초기 개발 및 테스트용으로는 Alibaba Cloud의 `Qwen 2.5` 1.5B/0.5B Instruct 모델이 주로 활용됨)*
* **LLM 추론 엔진 및 Unity 연동 플러그인:**
  * `LLM for Unity` / `LlamaSharp`: Unity C# 환경에서 LLM 네이티브 구동 및 Grammar 제약을 위해 사용.
  * `llama.cpp`: CPU/GPU 환경에서 GGUF 모델 추론 최적화를 수행하는 백엔드 엔진.
* **LLM 모델 파인튜닝 / 훈련 유틸리티:**
  * `Unsloth`: 초고속 대규모 언어 모델 QLoRA 파인튜닝을 지원하는 오픈소스 라이브러리 (요미 전용 대화 데이터셋 `yomi_dataset.jsonl` 학습에 활용).

### 5.2. 생성형 아트 에셋 제작 툴
* **생성형 AI 워크플로우:** Stable Diffusion 등 Image-to-Image 기반 파이프라인
  * **출처/도구:** Stable Diffusion WebUI, ControlNet 등
  * **용도:** 확정된 오리지널 스프라이트(Reference)를 바탕으로, 원본과 동일한 동작과 구도를 완벽히 유지한 채 다양한 코스튬(유카타, 한복 등) 이미지를 게임 규격(600×1180)에 맞추어 일관성 있게 생성.
