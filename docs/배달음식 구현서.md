# 배달 음식 카테고리 신설 및 시스템 구현 계획

이 문서는 새롭게 추가될 '배달 음식' 상점 카테고리와 이로 인한 임시 버프(추가 효과) 시스템을 구현하기 위한 계획서입니다.

## ⏱️ 추가 효과(버프) 지속 시간 계산 및 설정

요구사항 7번에 따라 우리 게임의 시간 흐름에 맞춰 배달 음식의 임시 버프 지속 시간을 계산했습니다.

*   **현재 게임 시간 배속:** 1초(현실) = 1분(인게임)
*   **게임 내 하루 진행 시간:** 09:00 ~ 24:00 (총 15시간 = 인게임 900분)
*   **하루를 현실 시간으로 환산:** 900초 = **정확히 15분**

즉, **현실 시간 1분이 인게임 시간 1시간**과 정확히 일치합니다.
이를 바탕으로, 배달 음식의 추가 효과가 게임 밸런스에 너무 큰 영향을 주지 않으면서도 충분히 체감될 수 있도록 **기본 버프 지속 시간을 현실 시간 3분 (인게임 3시간)** 으로 설정했습니다. (파스타는 지속 시간 동안 시간이 1.5배 빨리 흐릅니다.)

## 🍔 신규 배달 음식 아이템 목록 및 가격 상세 효과

기존 상점 아이템 4종(디저트 $600, 에너지드링크 $500, 영양제 $900, 진정제 $1,000)의 가성비(체력 1당 약 $18, 멘탈 1당 약 $25)를 기준으로 하되, 한 번에 대량의 수치를 회복시켜 주거나 버프를 제공하는 편의성을 고려해 적절한 프리미엄을 더한 합리적인 가격으로 재조정했습니다. 
(예: 엽떡의 원가 가치는 체력30($540) + 멘탈60($1500) = $2,040 수준이나, 할인을 적용해 $1,500으로 책정)

아래 가격표는 **'기본 가격(Base Price)'** 이며, 게임 내 **'아이템 가격 인플레이션(2일마다 20% 상승)'** 로직이 배달 음식에도 동일하게 적용됩니다.

| 아이템 이름 | 기본 가격 | 회복 효과 (체력 / 멘탈) | 추가 버프 효과 (최대 2개 적용 제한) | 지속 시간 (현실 기준) | 쿨타임 / 조건 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **마라탕** | **$1,300** | 체력 **+25** / 멘탈 **+50** | (없음) 즉시 회복용 | - | 상시 |
| **초밥** | **$1,400** | 체력 **+30** / 멘탈 **+55** | (없음) 즉시 회복용 | - | 상시 |
| **엽떡** | **$1,500** | 체력 **+30** / 멘탈 **+60** | (없음) 즉시 회복용 | - | 상시 |
| **파스타** | **$1,200** | 체력 **+15** / 멘탈 **+15** | **[시간 가속]** 인게임 시간이 1.5배 빠르게 흐름 | **3분** (인게임 4.5시간 경과) | 상시 |
| **스테이크** | **$35,000** | 체력 **100%** / 멘탈 **100%** 회복 | **[스탯 상승]** 멘탈 최대 한계치(MaxMental) **+10** 상승 | 영구 지속 | 업적 해금 시,<br>1주일에 한 번 |

*(인게임 아이템 툴팁에는 "지속 시간: 3시간"과 같이 인게임 시간을 기준으로 텍스트가 표기됩니다.)*

## 파스타 아이템 (시간 가속 1.5배)의 LLM 돌발 이벤트 영향 분석

요구사항 6번에 대한 분석 결과입니다.

현재 `ChoiceEventController.cs`를 분석해 본 결과, LLM 텍스트 사전 생성은 돌발 이벤트 발생 예정 인게임 시간으로부터 **60분 전**에 시작됩니다.
* **기본 배속 시 (1초 = 1분):** 60분 전 = 현실 시간 **60초 전**에 LLM 호출 시작
* **파스타 가속 시 (1.5배속, 0.66초 = 1분):** 60분 전 = 현실 시간 **40초 전**에 LLM 호출 시작

모바일 환경에서 LLM 응답이 늦어져 40초를 초과하여 이벤트 발생 시각이 다가오더라도 게임에는 문제가 없습니다!
현재 코드의 `ChoiceEventController.cs` 202번째 줄에 다음과 같은 **안전 장치**가 이미 튼튼하게 구현되어 있습니다.
```csharp
// 💡 LLM 텍스트 생성이 아직 안 끝났다면, 이벤트 발생을 10분씩 계속 뒤로 미뤄서 게임을 멈추지 않고 기다려 줍니다!
if (isFetchingLLM)
{
    nextRandomTriggerMinuteOfDay += 10;
    return;
}
```
따라서, 1.5배로 시간이 가속되어 LLM 응답이 40초를 넘기더라도, 시스템이 알아서 이벤트 발생 시각을 10인게임분(가속 시 약 6.6초) 단위로 부드럽게 뒤로 미뤄주므로 **출력이나 돌발이벤트 진행에 전혀 문제가 없습니다.**

## Proposed Changes

새로운 `DeliveryFoodManager`를 도입하여 요구하신 규칙에 맞게 임시 버프(최대 2개 유지, 우선순위 관리)를 전담하게 합니다. 현재 임시 버프는 파스타 뿐이지만 향후 추가될 버프들을 대비해 2개 유지 시스템 구조를 미리 잡아둡니다.

### Core Systems

#### [NEW] DeliveryFoodManager.cs
임시 버프 관리를 위한 신규 싱글톤 매니저입니다.
- **기능:**
  - 활성화된 배달 음식 버프 리스트(최대 2개) 관리
  - 3번 규칙: 동일 버프 재사용 시 `지속시간 새롭게 갱신`
  - 4번 규칙: 서로 다른 3번째 버프가 들어올 시 `가장 오래된 버프 제거 후 새 버프 추가`
  - 버프에 따른 실시간 타이머 작동 (현실 시간 기준 `Time.unscaledDeltaTime` 사용)
  - 외부(TraderStatus, ActiveItemEffectManager 등)에서 특정 버프가 활성화되어 있는지 묻는 API 제공
- 파스타 효과 발동 시 `DynamicTimeRegulator.Instance.TriggerDramaticSlowMotion(0.666f, 현실 3분)`을 호출하여 1.5배 가속 적용 (기본 1.0f 대비).

#### [MODIFY] ItemData.cs
- `EffectType` enum에 배달음식 버프 타입들을 추가합니다 (예: `Food_TimeAccel`, `Food_MaxMentalUp` 등).
- 배달음식은 여러 효과(체력+멘탈 동시 회복 등)를 가지므로 `ItemUser.cs`에서 특정 ID나 타입에 따라 하드코딩된 수치를 동시에 부여하게 합니다.

#### [MODIFY] ItemUser.cs
- 배달 음식 사용 시의 분기 처리를 추가합니다.
- 예: 초밥 사용 시 체력 +30, 멘탈 +55 회복. 파스타 사용 시 체력/멘탈 회복 후 `DeliveryFoodManager.Instance.AddBuff(BuffType.Pasta, 현실3분)` 호출.
- 스테이크 사용 시 쿨타임(마지막 구매일로부터 7일) 체크 로직 추가 및 멘탈 최대치(MaxMentalLimit) 영구 상승 적용.

### UI & Assets

#### [NEW] 배달 음식 Asset 생성
- `Assets/Data/Items/Food/` 폴더 하위에 마라탕, 초밥, 엽떡, 파스타, 스테이크의 `ItemData` 에셋 파일들을 생성합니다.
- 각 아이템의 설명 텍스트에 지속시간(인게임 시간 기준)을 명시합니다. (예: 파스타 "효과 지속: 인게임 3시간")

#### [MODIFY] ShopManager.cs 및 DynamicShopUI.cs
- 상점에 '배달 음식' 탭을 추가하고, 이 탭이 선택될 때 새로 생성한 배달 음식 에셋 목록을 동적으로 로드하여 UI에 표시합니다.
