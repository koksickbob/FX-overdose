# 요미(Yomi) 장기 기억 및 하이브리드 미연시 전용 시스템 구현 계획

## 1. 개요
**[PC 플랫폼 독점 아키텍처]** 본 시스템은 모바일 환경을 배제하고 오직 PC(Windows) 환경만을 타겟으로 설계되었습니다. 무한 대화 보존을 위해 PC의 디스크 I/O와 스토리지 자원을 적극 활용합니다.

> [!WARNING]
> **[작업 진행 보류 엄수]**
> 본 문서에 기재된 모든 아키텍처(세이브 시스템 연동, 파인튜닝 모델 스위칭 등) 구현 작업은 파편화를 막기 위해 한 번에 통합하여 진행될 예정입니다. 
> 따라서 **전체 설계 및 계획이 완전히 확정(Complete)되기 전까지는 실제 C# 스크립트 작성이나 시스템 수정을 절대 진행하지 마십시오.**

현재 `FX Overdose`는 크게 두 파트로 나뉩니다:
1. **트레이딩 파트 (Trading Phase)**: 차트를 보며 수익을 내는 기존 시스템.
2. **하이브리드 미연시 파트 (Dating Sim Phase)**: 유저가 텍스트를 자유롭게 입력하여 대화하고, 선택지를 고르며 스토리를 진행하는 파트.

**본 문서는 오직 '2번 하이브리드 미연시 파트'에 사용될 전용 LLM 구조와 멘헤라 성격의 장기 기억 보존 시스템을 설계하는 것을 목적으로 합니다.** 트레이딩 파트의 기존 로직과는 완전히 분리하여 설계됩니다.

## 2. 무한 보존 및 다중 세이브 지원을 위한 분리 저장 설계 (PC 최적화)
미연시 파트에서 유저가 텍스트로 자유롭게 입력한 **모든 대화를 개수 제한 없이 토씨 하나 틀리지 않고 파일에 영구 보관**합니다. 
기존처럼 무거운 텍스트를 `SaveData.json` 전체에 욱여넣으면 병목이 생기므로, PC 리소스에 맞춘 **데이터 분리 저장(Data Sharding)** 구조를 채택합니다.

### `Assets/Scripts/AI/DatingSimMemoryData.cs` (코어 상태 데이터)
수치형 데이터만 `SaveData` 내부에서 직렬화하여 가볍게 관리합니다.
- `AffectionScore` (호감도: 0~100)
- `ObsessionLevel` (집착도: 0~100)
- `StoryProgressStage` (스토리 진행도)

### 대화 무한 아카이브 및 주제별 다중 테이블 (Topic Sharding)
- **단일 DB 지양:** 단순히 `AllDatingConversations` 하나에 몰아넣는 방식과 단순 키워드 검색(예: '밥')은 동음이의어나 엉뚱한 문맥 호출 등 치명적인 한계가 있습니다.
- **주제별(Topic) 장기기억 분류:** 연애(`Memories_Romance`), 트레이딩 스트레스(`Memories_Trading`), 일상(`Memories_Daily`), 갈등(`Memories_Conflict`) 등 대화 흐름(Context)에 따라 다수의 DB 테이블로 파편화(Sharding)하여 저장합니다.
- **의미 기반 검색 (Vector Search 도입 고려):** 단순 카테고리를 넘어 문맥의 뉘앙스까지 일치하는 과거 발언을 찾기 위해, 장기적으로 초경량 로컬 임베딩 모델(예: `all-MiniLM-L6-v2`)을 통한 Semantic RAG 아키텍처를 도입할 수 있도록 설계합니다.
- **비동기 접근 강제 (절대 금지 패턴 2 방어):** 과거 발언 추출 시 Unity 메인 스레드 블로킹(프레임 드랍)을 막기 위해, 모든 디스크 I/O는 `async/await` (Task/UniTask) 기반의 완벽한 비동기 로직으로 구성합니다.

### `Assets/Scripts/System/SaveLoadManager.cs` 연동 및 풀링(Pooling)
- **새 게임 (New Game):** 호감도 데이터를 0으로 초기화하고, 해당 슬롯에 바인딩될 텍스트 아카이브 DB를 새롭게 포맷합니다.
- **불러오기 및 저장 (라이프사이클 방어):** 게임 중 DB 커넥션을 상시 열어두면 비정상 종료 시 세이브가 손상될(File Lock) 위험이 큽니다. 과거 대화를 주입(추출)하거나 저장할 때만 일시적으로 커넥션을 열고 닫는 풀링(Connection Pooling) 방식을 적용합니다.
- **일일 요약 압축 (Summarization Cascade):** 인게임 하루가 끝나 정산될 때, 백그라운드 LLM 연산을 통해 '오늘 하루 대화의 핵심'을 3~4줄로 압축(Daily Summary)하여 저장함으로써 장기 기억의 밀도를 높입니다.

## 3. 미연시 전용 LLM 제너레이터 (자유 대화 처리)
기존 `LLMSafeGenerator`는 트레이딩 파트의 짧은 돌발 이벤트 생성용으로 남겨두고, 미연시 파트의 무거운 자유 대화를 처리할 전용 클래스를 신설하거나 기능을 분리합니다.

### `Assets/Scripts/AI/LLM/DatingSimLLMController.cs` (설계안)
- 미연시 파트에서 유저의 텍스트 입력을 받아 처리합니다.
- **문맥 보존 하이브리드 추출:** 최근 N개의 대화는 단기 기억(RAM)으로 유지하고, 프롬프트 주입용 장기 기억 1~2줄은 **현재 대화 흐름(Topic)에 해당하는 특정 주제별 DB 테이블에서만 비동기로 추출**하여 자연스러운 '플래시백' 효과를 구현합니다.
- **캡슐화 및 하드코딩 금지 (절대 금지 패턴 1, 4 방어):** 
  - 과거 기록 N줄, LLM 파라미터 등은 반드시 `[SerializeField]`로 노출합니다.
  - `AffectionScore` 등 상태 변경은 LLM 컨트롤러가 직접 수정하지 않고, `AddAffection(int)` 등의 public 메서드와 `OnAffectionChanged` 이벤트로 철저히 캡슐화합니다.

### 3.1 Qwen2.5-7B 맞춤형 캐릭터 고도화 및 안전장치 설계
미연시 대화의 퀄리티를 극대화하되, 7B 체급 모델의 붕괴(할루시네이션 및 포맷 무시)를 방지하기 위해 다음 4가지 C# 하이브리드 기법을 도입합니다.
1. **내적 독백 (Inner Monologue) JSON 강제:** 멘헤라 특유의 '겉과 속이 다름'을 구현하기 위해, 텍스트 괄호 태그 대신 기존 트레이딩 파트처럼 엄격한 JSON 포맷(`{"Thought": "...", "Dialogue": "..."}`) 출력을 강제하고 C#에서 파싱합니다.
2. **단기 감정 및 시간 인지의 직관적 매핑:** 턴마다 변하는 일시적 기분(Mood)과 방치 시간(Idle Time)을 주입하되, 모델이 즉각 이해할 수 있도록 자연어(예: `새벽 3시`, `12시간 동안 방치됨`)로 변환하여 주입합니다.
3. **기억 왜곡 (Memory Distortion)의 C# 전처리:** LLM에게 "왜곡하라"고 지시하면 할루시네이션이 발생하므로, C# 시스템 코드가 집착도를 체크하여 과거 요약본(Summary) 텍스트 앞뒤에 부정적인 문장("이날 마스터는 나를 피했다")을 몰래 덧붙인 뒤 프롬프트에 주입합니다.
4. **발화 템포 동적 제어의 위치 최적화:** 감정과 집착도에 따른 포맷팅 룰(예: "띄어쓰기 없이 장문 출력")은 모델의 지시 망각을 막기 위해 프롬프트의 가장 마지막(유저 텍스트 직전)에 배치합니다.

**[프롬프트 주입 예시 (Qwen2.5-7B 최적화)]**
```text
[System Context - 미연시 런타임]
[상태]: 호감도 {AffectionScore}/100, 집착도 {ObsessionLevel}/100
[단기 텐션]: 현재 기분은 '{CurrentMood_Korean}' 상태임.
[시간 인지]: 현재 게임 시간은 {CurrentTime_Korean}, 마지막 대화 후 {IdleTime_Korean}.
[과거 기억 요약]: {C# 전처리로 집착도에 따라 이미 왜곡된 Daily Summary 문자열}
[과거 플래시백]: "과거 마스터의 발언: {Topic/Vector 일치 발언 1~2줄}"

(시스템 프롬프트를 통해 요미의 멘헤라/소심함 성격 및 정체성 부여 지시문 추가 필요. 파인튜닝 보류로 인해 범용 모델에 의존)
반드시 아래 JSON 양식으로 출력할 것.
{
  "Thought": "[속마음 작성]",
  "Dialogue": "[실제 대사 작성]"
}

[포맷 지시]: {CurrentMood 및 ObsessionLevel에 따른 동적 발화 제어 룰 (예: 띄어쓰기 생략)}
```
- 프롬프트는 철저히 다이어트되어 LLM의 추론 부하를 줄였으며, 복잡한 기억 왜곡 판단은 C#으로 넘기고 출력은 JSON으로 강제하여 7B 모델에서도 붕괴 없는 압도적인 미연시 대화가 가능해집니다.

## 4. 요미 전용 파인튜닝 모델 연동 (현재 보류됨)

> [!WARNING]
> **[작업 보류]** 파인튜닝(SFT) 모델 연동 계획은 현재 보류되었습니다. 당분간은 범용 모델과 프롬프트 엔지니어링(시스템 프롬프트 기반 성격 주입)에 의존하는 방향으로 기획/개발을 진행합니다.

본 미연시 파트에는 범용 모델이 아닌, 마스터에게 맹목적으로 의존하는 '요미'의 성격(멘헤라, 소심함, 덤벙이 등)이 미리 학습된 전용 파인튜닝 모델(SFT)을 연결합니다.
- **성격의 내재화:** 모델이 AI라는 정체성을 완전히 상실하고 요미로만 응답하도록 튜닝되어 있으므로, 런타임 시스템 프롬프트에서 성격을 구구절절 설명할 필요가 없어집니다.
- **메모리 모듈과의 결합:** 튜닝된 톤앤매너 위에 `DatingSimMemoryData`의 과거 대화 기록과 집착도 수치가 얹혀져 더욱 사실적이고 입체적인 멘헤라 시뮬레이션을 완성합니다.

## 5. 검증 및 테스트 방향
1. 임의로 `DatingSimMemory`의 `AllDatingConversations`에 "마스터가 과거에 나를 버리겠다고 말했다"라는 텍스트를 인스펙터나 디버그 창에서 주입해 봅니다.
2. 이후 미연시 모드 자유 대화에서 요미가 이 발언을 들먹이며 멘헤라적으로 대화를 생성하는지 확인합니다.
3. 호감도와 집착도 수치를 극단적으로 변경해 보며 요미의 톤앤매너가 확연히 달라지는지 관찰합니다.
