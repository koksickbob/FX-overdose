## 1. 범위

호감도·의존도 두 축의 **규칙**과 **챕터 진행**을 담당한다. 이벤트 재생(D2), 장소(D3), 엔딩 판정(D4)은 전부 여기의 수치를 읽기만 한다.

이 문서가 끝나면 다음이 가능해야 한다 — 챕터를 올리면 의존도가 자동 감소하고, 챕터2에서 호감도가 50을 넘지 못하며, 임의의 시점에 "현재 좌표가 어느 구간인가"를 한 줄로 물어볼 수 있다.

## 2. 현행 코드 상태

| 항목 | 상태 |
| --- | --- |
| `currentAffection` / `currentObsession` (0–100 클램프) | **있음** |
| `ModifyAffection` / `ModifyObsession` | **있음** — 호출 즉시 디스크 저장 |
| `peakAffection` (대화 토픽 해금용 최고치) | **있음** |
| `StoryProgressStage` | **있음** — 다만 현재 용도가 대화 해금 단계이며 챕터가 아니다 |
| `SaveData.DatingAffection` / `DatingObsession` | **있음** |
| 챕터 개념 · 챕터별 상한 · 자연 감소 · 구간 판정 · 대화 횟수 제한 | **없음** |

> `ModifyAffection`은 자체적으로 저장한다. 수치를 건드리는 새 경로를 만들 때 **한 동작에서 두 번 이상 호출하지 말 것** — 디스크 쓰기가 그만큼 늘어난다. D2의 지연 커밋 버퍼가 이미 그 이유로 존재한다.

## 3. 구현 항목

### 3.1 챕터 상태 (`DatingChapter`)

`StoryProgressStage`를 전용하지 말고 **별도 필드를 신설한다.** 전자는 대화 토픽 해금에 이미 묶여 있어 의미가 겹치면 조용히 어긋난다.

```
DatingChapter : 1 → 2 → 3 → 4 → 5        (정석)
                     3 → 4B → 5B          (CP2 부정 시)
```

- `SaveData.DatingChapter` (int, 기본 1) 신설. `SaveDataMigrator`에 backfill — 기존 세이브는 `DatingDay`/`StoryProgressStage`로 추정하지 말고 **1로 시작**시킨다(Phase 2 세이브가 아직 배포 전이므로 추정 로직은 낭비다).
- B루트는 음수나 별도 열거가 아니라 `DatingChapter` + `SaveData.IsBadRoute`(bool) 조합으로 표현한다. 챕터 번호 산술(상한·자연 감소)이 A/B 공통이기 때문이다.
- 챕터 전이는 **월드맵 단계 해금과 같은 순간**에만 일어난다(D3). 즉 CP 이벤트 완료가 유일한 트리거다.

### 3.2 챕터 전환 훅 (`AdvanceChapter`)

전이 시 순서대로 처리한다.

1. `DatingChapter` 증가 (또는 B루트 진입 시 `IsBadRoute = true`)
2. **의존도 자연 감소 −10** — 단 직전 체크포인트가 부정 판정이었으면 **건너뛴다**
3. 챕터별 호감도 상한 재적용 (3.3)
4. 일일 대화 카운터 리셋 (3.5)
5. 저장 1회

> §4.1: "챕터가 넘어갈 때마다 의존도가 자동으로 10 감소한다. … 단 직전 체크포인트에서 부정 판정을 받았다면 감소하지 않는다."
> 이 −10이 없으면 상승 편향 때문에 **평온 구간(0–25)을 요구하는 진엔딩·굿엔딩에 도달할 수 없다.** 감소를 빼먹으면 엔딩 절반이 사라지므로 D4보다 먼저 검증한다.

별개로 **월드맵 단계 해방 시 의존도 −10 고정**이 §4.1 변화폭 표에 있다. 챕터 전환과 월드맵 해금이 같은 순간이라면 **두 번 빼지 않도록** 한 곳에서만 처리한다 — `AdvanceChapter` 안에 둔다.

### 3.3 챕터별 호감도 상한

절대값 천장이다(챕터당 상승 총량 제한이 아님).

| 챕터 | 호감도 상한 | 도달 가능 최고 구간 |
| --- | ---: | --- |
| 2 | 50 | 관심 |
| 3 · 4 · 5 (및 B루트) | 100 | 제한 없음 |

- `ModifyAffection` 내부에서 `Mathf.Clamp(value, 0, ChapterAffectionCap)` 으로 처리한다. 호출자마다 클램프하면 넷째 호출자에서 빠진다.
- 상한에 걸려 잘린 경우에도 `peakAffection`은 잘린 값 기준으로 갱신한다(대화 해금이 상한을 우회하면 안 됨).
- 챕터가 올라가 상한이 풀릴 때 **소급 복구는 하지 않는다.** 잘린 값이 그대로 현재값이다.

### 3.4 구간(티어) 판정

§4.1의 구간 정의를 단일 헬퍼로 제공한다. D4의 엔딩 격자, D3의 꽃 지표, CP4의 구간 이동이 전부 이것을 쓴다.

| 호감도 | 구간 | 의존도 | 구간 |
| --- | --- | --- | --- |
| 0–25 | 무관심 | 0–25 | 평온 |
| 26–50 | 관심 | 26–50 | 불안 |
| 51–75 | 신뢰 | 51–75 | 밀착 |
| 76–100 | 애정 | 76–100 | 집착 |

- **구간 이동**(CP4 전용): 한 구간 위/아래로 옮길 때 **해당 구간의 중앙값으로 대입**한다(신뢰→애정이면 88). 최상단/최하단에서는 그 방향으로 움직이지 않는다.
- ⚠️ **구간명은 내부 명칭이다.** 게임 화면에는 "신뢰 단계"가 아니라 `호감도 63` 같은 원시 수치를 그대로 표시한다(§4.1 주석). UI에 구간명을 쓰지 말 것.
- 의존도 노출 여부는 상위 문서 §7-1의 미결정 사항이다. **숨기는 쪽으로 확정되면 이 헬퍼는 순수 내부용이 되고 UI 작업이 통째로 사라진다.**

### 3.5 일일 대화 횟수 제한

일일 대화는 반복 제한이 없어 오래 굴린 플레이어가 선택과 무관하게 수치를 채운다.

- **챕터당 N회까지만 수치가 변하고, 이후로는 대사만 진행된다.** N은 §4.1 기준 10–15회, **미정**. 상수 하나로 빼고 밸런싱 때 조정한다.
- 카운터는 `SaveData`에 챕터 단위로 저장하고 `AdvanceChapter`에서 리셋한다. 일 단위가 아니다 — 일 단위로 자르면 날짜만 넘겨 다시 채울 수 있다.
- 적용 대상은 요미의 방 `ChoiceTalk`뿐이다. 이벤트(D2)는 1회성이므로 제한 대상이 아니다.

### 3.6 수치 변화폭 우선순위 (밸런싱 가드)

§4.1이 정한 서열이다. 데이터 입력 시 검증용으로만 쓴다.

```
주요 이벤트(CP) > 메인 이벤트 > 서브 이벤트 ≥ 일일 대화(1–3) · 월드맵 해방(의존 −10 고정)
```

- 의존도는 **비대칭**이다 — 상승 +1~+10, 하락 −2~−6이며 하락 선택지 자체가 드물다. 콘텐츠 입력 시 이 비율을 깨지 말 것.
- 이벤트 유형 3종(관계 진전형 / 성향 결정형 / 복합형)은 §4.1-5 분류표에 챕터별로 이미 지정되어 있다. D2의 데이터 변환 시 그대로 따른다.

## 4. 세이브 확장

| 필드 | 용도 |
| --- | --- |
| `DatingChapter` (int, 기본 1) | 현재 챕터 |
| `IsBadRoute` (bool) | CP2 부정 판정 후 B루트 |
| `LastCheckpointNegative` (bool) | 자연 감소 스킵 판정용 |
| `ChapterTalkStatCount` (int) | 챕터 내 수치 반영된 대화 횟수 |

`SaveDataMigrator.Migrate()`에 버전 비교 백필을 추가한다. 네 필드 모두 기본값이 안전하므로 백필은 "없으면 기본값" 수준이면 충분하다.

## 5. 완료 판정

에디터에서 다음이 재현되면 끝이다.

1. 챕터2에서 호감도 +10 선택지를 반복해도 **50에서 멈춘다.**
2. 챕터3으로 넘기면 의존도가 **−10** 되고, 직전 CP를 부정으로 통과했을 때는 **감소하지 않는다.**
3. 호감도 63 / 의존도 30 상태에서 구간 헬퍼가 `신뢰` / `불안`을 돌려준다.
4. 구간 이동(+1)을 호출하면 63 → **88**이 된다.
5. 저장 후 재시작 시 챕터·루트·카운터가 그대로 복원된다.

## 6. 하지 않는 것

- 의존도 상한. §4.1-2가 명시적으로 **두지 않는다**(챕터3 시점에 집착 구간 도달이 가능해야 구속·자해 엔딩이 성립).
- 호감도 자연 감소. 규칙에 없다.
- 구간명 UI 노출. 3.4 참고.
- 엔딩 판정. D4의 몫이다. 여기서는 수치와 구간만 제공한다.
