## 1. 목적

통합 시나리오 문서 한 권(7,568줄)을 **구현 가능한 작업 단위로 쪼개기 위한 분할 기준**을 정한다. 이 문서는 분할의 축과 하위 문서 목록만 정의하며, 각 항목의 상세 설계는 하위 문서에서 다룬다.

분할 대상은 세 종류다 — **시스템(코드) · 콘텐츠(텍스트→데이터) · 에셋(배경/스탠딩/CG)**. 이 셋은 담당도, 완료 판정도, 병렬 가능 여부도 다르므로 한 문서에 섞지 않는다.

**A1의 핵심 절감 규칙 두 가지:**

1. **B루트 배경은 재제작이 아니라 그레이딩 variant다.** 통합 문서의 B루트 연출 원칙이 "이미 열려 있던 장소들이 **색이 바랜** 부정적 버전으로 교체"이므로, 같은 원화에 채도/명도 그레이드만 다르게 적용한다. B루트 15건이 사실상 추가 원화 0장이 된다.
2. **계절은 장소별로 최소 1개만 잡는다.** 챕터가 계절을 따라가지만(여름-가을 → 겨울 → 봄 → 여름), 대부분의 장소는 한 챕터에만 등장한다. A1에서 실측한 결과 계절이 실제로 바뀌는 곳은 **B루트 5-B에서 재등장하는 1단계 장소 4곳뿐**이고, 그중 실내 3곳은 그레이딩으로 흡수되어 **추가 원화는 산책로 봄 variant 1장**이다.

**A3의 연속성 소품** — 무드등(챕터2 [집-잠] → 챕터4 [집-혼자있는밤]), 화분(챕터2 [꽃집-1] → 진엔딩 #2), 반지(챕터5 [반지공방-1] → 진엔딩 #12, 삐뚤어야 함), 즉석사진(챕터4 → 냉장고), 스케치북(챕터5 [집-스케치북] → 진엔딩에서 그림을 그리는 요미). 진엔딩에서 회수되는 장치라 디자인을 고정해야 한다. 화분·반지·#19 구도는 통합 문서의 [진엔딩] 연출 메모가 직접 지정한 항목이다.

**A3의 최우선 제약** — 진엔딩 #19의 구도는 **CP4 전망대 씬과 픽셀 단위로 동일**해야 한다(유리에 닿은 손끝이 앵커). 전망대 배경과 진엔딩 CG는 같은 작업 묶음으로 발주한다.

## 5. 착수 순서

```
D1 수치·진행 코어
 ├─ D2 이벤트 런타임 확장 ─→ C2 챕터2 ─→ C3 ─→ C4 ─→ C5 ─→ C6 ─→ C7
 ├─ D3 월드맵·장소·꽃집
 └─ D4 분기·엔딩·자산  (D3 이후)

A1 배경 / A2 스탠딩 매핑 / A3 CG  — 전 구간 병렬, 단 A2는 C2 착수 시점에 필요
```

수직 슬라이스 우선: **D1 → D2 → C2(챕터 2) → D3 → CP1까지 한 챕터를 끝까지 굴려본 뒤** 나머지 챕터를 양산한다. 챕터 2는 이벤트 18건 중 메인 10건이고 CP1이 판정 없는 단순 진입이라, 전체 루프를 검증하기에 가장 싸다.

## 6. 분할하지 않을 것

- **이벤트 1건 = 문서 1개.** 74문서가 된다. 이벤트 단위 정보는 문서가 아니라 추적표의 행으로 관리한다.
- **수치 밸런스 문서 신규 작성.** 통합 문서 §4에 분류표·격자·좌표 지도·도달 가능 영역이 전부 있다. 하위 문서는 참조만 하고 수치를 복제하지 않는다 — 복제하면 두 곳이 갈라진다.
- **엔딩 18종 각각 문서.** §4.2 격자 + §4.3 설명 한 묶음으로 충분하다.
- **B루트 전용 에셋 문서.** A1 안의 variant 규칙으로 흡수한다.

## 7. 착수 전 결정 필요

1. **의존도를 플레이어에게 수치로 노출할 것인가.** §3.3은 꽃집이 추천하는 꽃을 유일한 루트 지표로 설계했다. 숨기는 쪽으로 확정하면 D1에서 의존도 UI 요구사항이 통째로 사라지고, 꽃집(D3)이 유일한 피드백 채널이 되므로 D3의 우선순위가 올라간다.
2. **인게임 텍스트 미작성 16건을 1차 범위에 넣을 것인가.** 전부 사이드 스토리(15)와 에덴엔딩(1)이라 빼도 메인 흐름과 모든 엔딩 분기는 성립한다. 빼면 콘텐츠 작업량이 74 → 58건이 된다.
