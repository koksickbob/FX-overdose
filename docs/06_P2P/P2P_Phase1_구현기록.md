# P2P Phase 1 구현 기록

## 1. 결과

네트워크나 Unity 씬 없이 플레이어 1~4명의 자산, 포지션, 주문, 손익, 청산, 탈락과 순위를 독립적으로 계산하는 P2P 코어를 구현했습니다.

검증 기준일: `2026-08-11`

Unity EditMode 테스트 결과:

```text
총 16개
성공 16개
실패 0개
```

## 2. 구현 파일

경로: `Assets/Scripts/P2P/Core/`

| 파일 | 역할 |
|---|---|
| `P2PMatchRules.cs` | 최대 인원, 레버리지, 마진 비율, 초기 자산, 수수료와 유지 증거금률 정의 |
| `P2PPlayerRuntimeState.cs` | 플레이어별 현금, 체력, 멘탈, 인벤토리, 포지션과 탈락 상태 보관 |
| `P2PPositionState.cs` | Long·Short 포지션, 진입가, 증거금, 레버리지와 미실현 손익 보관 |
| `P2PTradeRequest.cs` | 주문 요청, 거절 사유와 처리 결과 정의 |
| `P2PTradeValidator.cs` | 호스트가 권위 상태를 변경하기 전에 주문 유효성 검사 |
| `P2PTradeCalculator.cs` | Long·Short 손익, 진입·종료 수수료와 청산가 계산 |
| `P2PEliminationEvaluator.cs` | 총자산 0 또는 멘탈 0 즉시 탈락 판정 |
| `MultiplayerLeaderboard.cs` | 생존, 탈락 시점, 총자산과 Player ID 기준 결정적 순위 계산 |
| `P2PLocalMatch.cs` | 참가 등록, 경기 시작, 주문 처리, 중복 차단과 시장 가격 갱신 통합 |

## 3. 적용한 핵심 규칙

- 참가 인원은 1~4명입니다.
- 각 플레이어의 현금, 포지션, 체력, 멘탈과 인벤토리는 서로 독립적입니다.
- 클라이언트가 보낸 값은 바로 적용하지 않고 주문 검증기를 통과해야 합니다.
- 레버리지는 1부터 방장이 정한 최대 레버리지까지 허용합니다.
- 마진 비율은 0보다 크고 방장이 정한 최대 비율 이하여야 합니다.
- 주문 체결에는 호스트가 가진 현재 시장 가격을 사용합니다.
- 같은 플레이어가 같은 Request ID를 다시 보내면 중복 요청으로 거절합니다.
- 현금이 0이어도 포지션 증거금과 손익을 포함한 총자산이 남아 있으면 생존합니다.
- 총자산이 0 이하이거나 멘탈이 0 이하이면 한 번만 탈락 처리합니다.
- 같은 틱에 탈락한 플레이어는 총자산, Player ID 순으로 항상 동일하게 정렬합니다.

## 4. 기존 싱글플레이에서 재사용한 계산

기존 `TradingController`의 다음 규칙을 순수 C# 계산으로 옮겼습니다.

- Long 손익: `증거금 × 레버리지 × 가격 변화율`
- Short 손익: Long과 반대 방향의 가격 변화율
- 거래 수수료: `증거금 × 레버리지 × 0.0006`
- 유지 증거금률 기본값: `0.005`
- Long 청산가: `진입가 × (1 - 1/레버리지 + 유지 증거금률)`
- Short 청산가: `진입가 × (1 + 1/레버리지 - 유지 증거금률)`

UI, 사운드, 대사, 싱글톤과 `MonoBehaviour` 의존성은 가져오지 않았습니다.

## 5. 사용 기술 스택

### 순수 C# 도메인 모델

Unity의 `GameObject`나 씬 없이 게임 규칙만 표현하는 클래스입니다. 네트워크가 없어도 같은 입력에 같은 계산 결과를 만들 수 있고, 이후 호스트와 클라이언트 코드가 동일한 규칙을 재사용할 수 있습니다.

### Assembly Definition

Unity 스크립트를 별도 컴파일 단위로 나누는 `.asmdef` 기능입니다. `FXOverdose.P2P.Core`는 UnityEngine을 참조하지 않도록 설정해 네트워크 및 화면 코드와 분리했습니다.

### 호스트 권위 모델

클라이언트는 주문 요청만 만들고, 검증과 상태 변경은 호스트가 수행하는 구조입니다. 현재 `P2PLocalMatch`가 네트워크 없이 이 흐름을 재현하며 이후 NGO RPC의 서버 처리부가 이 API를 호출합니다.

### 불변 요청 및 결과 값

`readonly struct`로 주문 요청과 결과를 만들었습니다. 생성 후 값이 바뀌지 않아 검증 전후의 요청 내용이 달라지는 문제를 줄입니다.

### 결정적 정렬

순위가 같은 상황에서도 Player ID까지 비교해 모든 실행 환경에서 정렬 결과가 같도록 했습니다. 호스트와 참가자 HUD의 동점 순위 불일치를 방지합니다.

### Unity Test Framework와 NUnit

Unity에서 C# 규칙을 자동 실행하고 예상 결과와 비교하는 테스트 도구입니다. EditMode 테스트이므로 게임 씬을 실행하지 않고 빠르게 검증합니다.

## 6. 자동 테스트 범위

- 같은 가격 변화에서 Long·Short 반대 손익
- 진입 및 종료 수수료
- 기존 게임과 동일한 청산가 공식
- 최대 레버리지 및 마진 경계값
- 잘못된 레버리지와 마진 거절
- 중복 Request ID 차단
- 현금 0, 증거금 보유 시 생존
- 총자산 0 파산 및 중복 탈락 방지
- 멘탈 0 즉시 탈락
- 동일 틱 탈락 순위
- 한 시장에서 가상 플레이어 4명의 독립 Long·Short 거래
- 동일 Request ID의 플레이어별 독립 처리
- 청산 후 남은 총자산을 파산으로 오판하지 않는지 확인
