# FX Overdose P2P 멀티플레이 기획서 초안

## 1. 개요

`FX Overdose`의 **CHALLENGE 모드**를 기반으로 한 1~4인 경쟁 멀티플레이 모드입니다.

모든 플레이어는 AI 자동매매 없이 직접 LONG, SHORT, 청산을 조작합니다. 같은 시장과 같은 제한 시간 안에서 거래하며, 하루가 끝났을 때 시작 자산 대비 자산을 가장 많이 불린 플레이어가 승리합니다.

본 멀티플레이는 **Steam PC판 전용**으로 제공하며, Steam 로비와 Steam Networking을 사용합니다. 방장은 로비에서 경기의 최대 레버리지와 최대 마진 비율을 설정할 수 있습니다.

### 핵심 문장

> 같은 차트, 같은 시간, 같은 시작 자산에서 누가 가장 뛰어난 수동 트레이더인지 겨룬다.

### 기본 사양

| 항목 | 초안 규칙 |
|---|---|
| 참가 인원 | 1~4인 |
| 지원 플랫폼 | Steam PC판 전용 |
| 플레이 방식 | Steam Lobby 기반 P2P 방 생성 및 참가 |
| 기반 모드 | CHALLENGE |
| 매매 방식 | USER 수동매매 고정 |
| 경기 시간 | 인게임 1일, 09:00~24:00 |
| 예상 현실 시간 | 기본 배속 기준 약 15분 |
| 시작 자산 | 전원 동일 금액 |
| 레버리지·마진 | 로비장이 경기 상한 설정 |
| 승리 기준 | 최종 수익률 1위 |
| 탈락 조건 | 파산 또는 멘탈 0 |
| 저장 | 경기 진행 저장 없음 |

1인으로 방을 시작할 경우에는 기록 연습 또는 네트워크 테스트 모드로 동작합니다.

## 2. 기획 목표

### 2.1. 실력 중심의 짧은 경쟁

- 한 판을 인게임 하루로 제한해 결과가 빠르게 나옵니다.
- 자동매매를 완전히 금지하여 플레이어의 진입, 청산, 레버리지 및 증거금 판단이 결과를 결정합니다.
- 모든 플레이어에게 동일한 차트 흐름을 제공하여 운보다 매매 판단을 비교하기 쉽게 만듭니다.

### 2.2. 관전 재미

- 다른 플레이어의 현재 자산, 수익률, 포지션 방향과 순위를 실시간으로 표시합니다.
- 고레버리지 진입, 청산, 역전 등 중요한 순간을 전체 알림으로 보여줍니다.
- 최종 결과 화면에서 자산 곡선과 주요 기록을 비교할 수 있게 합니다.

### 2.3. 기존 시스템 재사용

- `GameMode.Challenge`의 AI 자동매매 잠금 규칙을 재사용합니다.
- 기존 `TradingController`, `MarketSimulationEngine`, `GameManager`, 차트 UI 및 일일 정산 흐름을 최대한 유지합니다.
- 멀티플레이 전용 코드는 방 관리, 시장 동기화, 플레이어별 상태, 순위 계산에 집중합니다.

## 3. 기본 게임 흐름

```text
[P2P 메뉴]
    ↓
[방 생성 또는 참가]
    ↓
[최대 4인 로비 / 전원 준비]
    ↓
[호스트가 경기 설정 확정]
    ↓
[공통 시장 시드 배포 및 동기화]
    ↓
[09:00 경기 시작]
    ↓
[플레이어별 수동 매매 + 실시간 순위 경쟁]
    ↓
[24:00 모든 포지션 강제 청산]
    ↓
[최종 수익률 기준 순위 및 결과 화면]
```

### 로비 설정 항목

- 방 이름
- 공개방 또는 비공개방
- 비공개방 초대 코드
- 최대 인원 2~4명
- 시작 자산
- 기본 경기 시간
- 최대 레버리지
- 최대 마진 비율
- 기본 캐릭터 케어 아이템 구성
- 돌발 이벤트 빈도

### 레버리지·마진 로비 설정

방장은 경기 시작 전에 모든 플레이어에게 공통 적용되는 위험 한도를 설정합니다.

| 설정 | 권장 프리셋 | 기본값 |
|---|---|---|
| 최대 레버리지 | `10x`, `25x`, `50x`, `75x`, `100x`, `125x` | `50x` |
| 최대 마진 비율 | `10%`, `25%`, `50%`, `75%`, `100%` | `50%` |

- 설정값은 모든 참가자에게 동일하게 적용합니다.
- 플레이어는 경기 중 허용된 상한 안에서 레버리지와 마진 비율을 자유롭게 낮추거나 높일 수 있습니다.
- 예를 들어 로비 설정이 `최대 50x / 최대 마진 50%`라면, 각 플레이어는 `1~50x`, `10~50%` 범위에서 선택할 수 있습니다.
- 참가자가 준비 완료한 뒤 방장이 설정을 변경하면 전원의 준비 상태를 해제합니다.
- 경기 시작 후에는 설정을 변경할 수 없습니다.
- 로비와 경기 HUD에 현재 제한값을 항상 표시합니다.
- 클라이언트 UI의 제한뿐 아니라 호스트가 주문을 받을 때도 상한을 다시 검증합니다.

MVP에서는 시작 자산과 경기 시간을 고정하고, 최대 레버리지와 최대 마진 비율만 핵심 경기 설정으로 제공합니다.

## 4. 경기 규칙

### 4.1. 공통 규칙

1. 모든 플레이어는 같은 시간에 09:00부터 시작합니다.
2. 모든 플레이어는 같은 시작 자산과 같은 시장 가격을 사용합니다.
3. AI 자동매매 및 AI·멘탈 기믹에 의한 강제 포지션 진입은 금지합니다.
4. 플레이어는 LONG, SHORT, 허용 범위 내 레버리지, 증거금 비율과 청산 시점을 직접 결정합니다.
5. 24:00에 열린 포지션은 현재가로 강제 청산합니다.
6. 최종 순위는 시작 자산 대비 최종 총자산 수익률로 결정합니다.
7. 호스트는 로비에서 확정된 최대 레버리지와 최대 마진 비율을 모든 주문에 강제 적용합니다.
8. 총자산이 0 이하가 되거나 멘탈이 0에 도달하면 즉시 탈락합니다.
9. 체력과 멘탈을 회복하는 캐릭터 케어 아이템은 사용할 수 있습니다.
10. 공통 경기 시간을 변경하는 아이템과 스킬 업그레이드는 사용할 수 없습니다.

### 4.2. 순위 계산

```text
최종 수익률(%) = (최종 총자산 - 시작 자산) / 시작 자산 × 100
```

최종 총자산에는 다음 값이 포함됩니다.

- 보유 현금
- 포지션 증거금
- 강제 청산 시 확정된 손익

### 4.3. 동률 처리

최종 수익률이 같을 경우 아래 순서로 순위를 결정합니다.

1. 최대 낙폭이 더 낮은 플레이어
2. 강제 청산 횟수가 더 적은 플레이어
3. 실현 수익 거래 횟수가 더 많은 플레이어
4. 마지막 수익 거래를 더 먼저 완료한 플레이어

### 4.4. 중도 탈락

플레이어는 아래 조건 중 하나를 충족하면 경기에서 즉시 탈락합니다.

#### 파산 탈락

```text
플레이어 총자산 <= 0
```

- 현금 잔고, 포지션 증거금과 미실현 손익을 합친 총자산을 기준으로 판정합니다.
- 현금만 0이고 포지션 증거금이 남아 있다면 파산으로 판정하지 않습니다.

#### 멘탈 붕괴 탈락

```text
플레이어 멘탈 <= 0
```

- P2P에서는 싱글플레이와 달리 멘탈 0에 도달하는 즉시 게임오버 처리합니다.
- 오버도즈 AI 강제매매와 35초 보호 시간은 적용하지 않습니다.
- 멘탈이 0이 된 뒤 아이템으로 회복하거나 추가 주문을 실행할 수 없습니다.

#### 탈락 처리 순서

1. 호스트가 파산 또는 멘탈 0 조건을 권위 상태에서 확정합니다.
2. 해당 플레이어의 신규 주문 입력을 즉시 차단합니다.
3. 열린 포지션이 있다면 호스트의 현재 시장 가격으로 강제 청산합니다.
4. 탈락 사유를 `BANKRUPTCY` 또는 `MENTAL OVERDOSE`로 기록합니다.
5. 모든 참가자에게 탈락 알림을 전송합니다.
6. 탈락한 플레이어를 관전 모드로 전환합니다.

- 탈락자는 생존 플레이어보다 아래 순위로 배치합니다.
- 여러 명이 탈락한 경우 더 오래 생존한 플레이어를 위에 배치합니다.
- 같은 시장 틱에 동시에 탈락한 경우 탈락 직전 총자산이 높은 플레이어를 위에 배치합니다.
- 모든 플레이어가 탈락하면 마지막까지 생존한 플레이어가 승리합니다. 완전 동시 탈락이면 위 동률 규칙으로 순위를 결정합니다.

### 4.5. 연결 종료

- 일시적인 연결 끊김에는 짧은 재접속 유예 시간을 제공합니다.
- 재접속 중인 플레이어의 신규 주문은 차단하지만 기존 포지션의 손익은 공통 시장 가격에 따라 계속 변합니다.
- 유예 시간 안에 복귀하지 못하면 기권 처리하고 열린 포지션을 시장가 청산합니다.
- 호스트가 나갈 경우 호스트 이전을 시도하며, MVP에서 이전이 어렵다면 경기를 무효 처리합니다.

### 4.6. 캐릭터 관리 및 아이템 규칙

P2P에서도 체력과 멘탈 관리가 승패에 영향을 주도록 캐릭터 케어 아이템을 사용할 수 있습니다.

#### 사용 가능한 아이템

- 에너지 드링크
- 디저트
- 영양제
- 진정제
- 체력 또는 멘탈을 즉시 회복하는 배달 음식
- 경기 시간을 변경하지 않는 일반 회복 아이템

#### 사용 금지 항목

- 파스타 등 인게임 시간을 빠르게 하거나 느리게 하는 아이템
- `DynamicTimeRegulator`의 배속에 영향을 주는 모든 버프
- 차트 공부, 큐브 풀기, 책읽기 등 모든 스킬 업그레이드
- 스킬 업그레이드에 따른 시간 경과 기능
- 개인 저장 데이터에서 가져온 액티브 장비와 영구 능력치 보너스

#### 공정성 규칙

- 모든 플레이어는 동일한 기본 체력, 멘탈과 최대치로 시작합니다.
- 개인 싱글플레이 세이브의 인벤토리와 스킬 레벨은 P2P에 반영하지 않습니다.
- 경기 시작 시 인벤토리는 동일한 기본 구성으로 초기화합니다.
- 상점에서 아이템을 구매할 경우 경기 자산을 실제로 지불해야 합니다.
- 구매 가능한 상품과 가격은 모든 플레이어에게 동일합니다.
- 아이템 사용 요청과 체력·멘탈 회복 결과는 호스트가 검증하고 확정합니다.
- 멘탈이 이미 0이 되어 탈락 판정이 확정된 뒤에는 회복 아이템을 사용할 수 없습니다.

MVP 기본 인벤토리 수량과 상점 가격은 기존 밸런스를 먼저 사용하고, 플레이 테스트 후 별도로 조정합니다.

### 4.7. 공통 돌발 이벤트 규칙

돌발 이벤트는 모든 생존 플레이어에게 동시에 발생하며, 각 플레이어가 제한 시간 안에 자신의 선택지를 결정합니다.

```text
이벤트 발생
→ 전원 입력 잠금 및 이벤트 UI 표시
→ 현실 시간 15초 선택 제한
→ 선택 확정 또는 시간 초과 시 무작위 선택
→ 호스트가 결과 일괄 처리
→ 경기 재개
```

#### 선택 시간

- 선택 제한 시간은 현실 시간 기준 `15초`입니다.
- 카운트다운은 `Time.unscaledDeltaTime`을 사용하여 게임 일시정지의 영향을 받지 않습니다.
- 이벤트 발생 중에는 공통 시장 시간과 가격 갱신을 일시정지합니다.
- 모든 생존 플레이어가 일찍 선택을 완료하면 15초를 기다리지 않고 즉시 결과 단계로 넘어갑니다.
- 한 번 확정한 선택은 변경할 수 없습니다.

#### 시간 초과 처리

- 15초 안에 선택하지 않은 플레이어는 호스트가 유효한 선택지 중 하나를 무작위로 선택합니다.
- P2P에서는 아이템을 소모하는 3안 선택지를 표시하거나 처리하지 않습니다.
- 미선택 무작위 후보는 일반 1안·2안으로 제한합니다.
- 무작위 선택 결과는 호스트가 확정하고 모든 클라이언트에 전송합니다.
- 재현과 검증을 위해 `MatchSeed + EventSequence + PlayerSteamId`를 이용한 결정적 난수를 사용합니다.

#### 공통 시장과 개인 선택 효과

모든 플레이어가 하나의 차트를 공유하므로 플레이어마다 서로 다른 시장 빔을 발생시킬 수 없습니다.

- 이벤트의 뉴스, 발생 시점, 시장 방향과 가격 빔은 전원에게 공통으로 적용합니다.
- 시장 결과는 이벤트 시작 시 호스트가 공통 시드로 미리 확정합니다.
- 플레이어의 선택에 따른 포지션 진입, 레버리지, 아이템 소모, 체력과 멘탈 변화는 플레이어별로 적용합니다.
- LONG과 SHORT처럼 서로 다른 방향을 선택한 플레이어는 같은 시장 결과에서 서로 다른 손익을 얻게 됩니다.
- 기존 싱글 이벤트 중 선택지가 시장 자체를 서로 다르게 변경하는 이벤트는 P2P 전용 데이터로 재구성해야 합니다.

#### 탈락자와 연결 지연

- 이미 탈락한 플레이어는 선택 대상에서 제외하고 이벤트를 관전만 합니다.
- 이벤트 도중 연결이 끊긴 플레이어는 시간 초과 시 무작위 선택 처리합니다.
- 이벤트 결과로 멘탈이 0 또는 총자산이 0 이하가 되면 결과 적용 직후 탈락 처리합니다.

## 5. 공정성 설계

### 5.1. 동일 시장 원칙

각 클라이언트가 별도의 난수 차트를 생성하면 가격이 달라질 수 있으므로, 한 경기에서는 하나의 공통 시장만 사용해야 합니다.

- 호스트가 경기 시작 시 `MatchSeed`를 생성합니다.
- 모든 참가자에게 동일한 시드와 시장 설정을 전달합니다.
- 호스트가 현재 가격, 인게임 시간과 시장 국면을 권위 상태로 관리합니다.
- 클라이언트는 받은 상태를 화면에 표시하고 로컬 예측은 시각적 부드러움에만 사용합니다.
- 일정 주기마다 체크섬 또는 가격 스냅샷으로 차트 불일치를 교정합니다.

### 5.2. 플레이어별 독립 상태

다음 정보는 플레이어별로 분리합니다.

- 현재 자산 및 총자산
- 포지션 방향
- 진입가
- 레버리지
- 투입 증거금
- 미실현·실현 손익
- 청산가
- 거래 및 청산 기록
- 현재 체력 및 멘탈
- 생존, 파산 또는 멘탈 붕괴 상태

한 플레이어의 주문은 다른 플레이어의 자산이나 포지션에 직접 영향을 주지 않습니다. 모든 플레이어는 같은 시장을 보고 각자 독립적으로 거래합니다.

### 5.3. 초기 MVP 권장 제한

경쟁 결과를 쉽게 검증하기 위해 첫 버전에서는 다음과 같이 단순화합니다.

- 전원 동일 레벨 및 스킬 수치
- 코스튬은 외형만 반영하고 능력치 보너스 없음
- 동일한 기본 인벤토리와 캐릭터 케어 아이템 사용
- 시간 가속 아이템 및 액티브 장비 비활성화
- 모든 스킬 업그레이드와 스킬 시간 경과 비활성화
- 전원 동시 15초 제한 돌발 선택 이벤트 사용
- 체력과 멘탈 시스템 유지
- 멘탈 0 도달 시 즉시 탈락
- Danger 및 Overdose 상태의 AI·기믹 강제매매 효과 금지
- 시간 가속 및 슬로우모션 비활성화
- 로비에서 설정한 레버리지와 마진 상한을 모든 플레이어에게 동일하게 적용

이후 별도 규칙으로 아이템전, 돌발 이벤트전 또는 성장 스탯 적용전을 추가할 수 있습니다.

## 6. 네트워크 구조 초안

### 6.1. 권장 구조: 호스트 권위형 P2P

Steam Lobby의 소유자가 호스트와 서버 역할을 함께 수행하는 Listen Server 구조를 사용합니다. 공개 로비 검색과 초대 전용 친구 로비는 Steam Matchmaking을 사용하고, 실제 경기 패킷은 Steam Networking을 통해 전송합니다.

```text
                 [Host / Authority]
                공통 시장·시간 관리
                주문 검증·순위 계산
                 /      |      \
             [P2]     [P3]     [P4]
             입력      입력      입력
```

호스트가 관리할 데이터:

- 방 및 참가자 목록
- 준비 상태
- 로비의 최대 레버리지 및 최대 마진 비율
- 경기 시작 및 종료
- 공통 인게임 시간
- 공통 시장 가격과 시장 시드
- 플레이어 주문 유효성 검증
- 플레이어별 자산과 포지션
- 플레이어별 체력, 멘탈과 탈락 상태
- 플레이어별 인벤토리와 아이템 사용 결과
- 돌발 이벤트 순번, 15초 제한 시간과 플레이어별 선택 상태
- 최종 순위

클라이언트가 호스트에 전송할 입력:

- LONG 진입 요청
- SHORT 진입 요청
- 포지션 청산 요청
- 레버리지 변경 요청
- 증거금 비율 변경 요청
- 아이템 구매 및 사용 요청
- 돌발 이벤트 선택 요청
- 준비 및 로비 상태

### 6.2. 주문 처리 원칙

클라이언트가 계산한 자산 결과를 그대로 신뢰하지 않습니다.

1. 클라이언트가 주문 요청과 입력 시각을 전송합니다.
2. 호스트가 현재 경기 상태, 잔고, 포지션과 제한값을 검증합니다.
   - 요청 레버리지가 로비의 최대 레버리지 이하인지 확인합니다.
   - 요청 증거금 비율이 로비의 최대 마진 비율 이하인지 확인합니다.
3. 호스트의 시장 가격을 기준으로 주문을 체결합니다.
4. 결과를 모든 참가자에게 전파합니다.
5. 각 클라이언트는 승인된 결과로 UI를 갱신합니다.

### 6.3. 지연 보정

- UI 클릭 직후 요청 중 상태를 짧게 표시합니다.
- 체결 가격은 호스트가 요청을 수신한 틱을 기준으로 합니다.
- 핑이 높은 플레이어에게 임의의 유리한 가격을 소급 적용하지 않습니다.
- 경기 시작 전 참가자의 지연 상태를 표시하고 과도한 핑에는 경고합니다.

### 6.4. 돌발 이벤트 네트워크 처리

1. 호스트가 `EventSequence`와 공통 시장 결과를 확정합니다.
2. 호스트가 이벤트 데이터와 종료 시각을 모든 생존 플레이어에게 전송합니다.
3. 각 클라이언트는 동일한 15초 카운트다운과 선택 UI를 표시합니다.
4. 클라이언트는 선택 번호만 호스트에 전송합니다.
5. 호스트가 아이템 보유량과 선택 가능 여부를 검증합니다.
6. 제한 시간 종료 시 미선택 플레이어의 선택을 결정적 난수로 확정합니다.
7. 호스트가 공통 시장 결과와 플레이어별 효과를 적용한 뒤 최종 상태를 전파합니다.
8. 모든 결과 처리가 끝나면 공통 시장 시간을 다시 시작합니다.

## 7. UI/UX 구성

### 7.1. P2P 메인 메뉴

- `CREATE ROOM`
- `JOIN ROOM`
- 공개방 목록
- 초대 코드 입력
- 최근 경기 기록

### 7.2. 대기실

- 참가자 1~4명 카드
- 닉네임 및 연결 상태
- 호스트 표시
- 준비 완료 상태
- 경기 규칙 요약
- 최대 레버리지 선택
- 최대 마진 비율 선택
- 초대 코드 복사
- 호스트 전용 시작 버튼

최대 레버리지와 최대 마진 비율 선택 UI는 방장에게만 활성화합니다. 다른 참가자에게는 현재 규칙을 읽기 전용으로 표시합니다.

### 7.3. 경기 HUD

기존 챌린지 HUD에 멀티플레이 정보를 추가합니다.

- 내 현재 순위
- 참가자별 닉네임
- 참가자별 총자산 및 수익률
- 참가자별 멘탈과 생존·탈락 상태
- 포지션 상태 아이콘: LONG, SHORT, NONE, LIQUIDATED
- 연결 상태 및 핑
- 남은 인게임 시간
- 로비에서 정한 최대 레버리지와 최대 마진 비율
- 전체 알림 피드

돌발 이벤트가 발생하면 경기 HUD 위에 전용 이벤트 팝업과 `15.0`초 카운트다운을 표시합니다. 다른 플레이어가 무엇을 골랐는지는 결과가 확정되기 전까지 숨기고, 선택 완료 여부만 체크 표시로 보여줍니다.

다른 플레이어의 정확한 레버리지와 증거금은 전략 노출을 막기 위해 기본적으로 숨기고, 포지션 방향과 수익률만 공개하는 방식을 우선 검토합니다.

### 7.4. 주요 전체 알림

- `PLAYER 2 — 50x LONG 진입`
- `PLAYER 3 — 포지션 청산, +42.5%`

- `PLAYER 2 — BANKRUPTCY / ELIMINATED`
- `PLAYER 3 — MENTAL OVERDOSE / ELIMINATED`
- `SUDDEN EVENT — 15초 안에 선택하세요`
- `PLAYER 4 — 시간 초과 / RANDOM OPTION`
- `RANK CHANGED — 현재 1위`
- `MARKET CLOSE — 모든 포지션 정산`

### 7.5. 결과 화면

- 최종 1~4위
- 최종 자산 및 수익률
- 생존 여부 및 탈락 사유
- 최고 도달 자산
- 최대 낙폭
- 총 거래 횟수
- 승리 거래 및 손실 거래 수
- 강제 청산 횟수
- 최고 ROE 거래
- 플레이어별 자산 변화 그래프
- 재대결 및 로비 나가기 버튼

## 8. 기존 시스템과의 연동 방향

### 재사용 대상

- `GameMode.Challenge`: 수동매매 고정 규칙
- `SaveLoadManager.AllowsAITrading`: AI 사용 제한
- `TradingController`: LONG, SHORT, 청산 및 손익 계산
- `MarketSimulationEngine`: 공통 시장 생성의 기반
- `GameManager`: 09:00~24:00 시간 및 정산 흐름
- `TopStatusBarUIController`: 자산, PnL, 시간 표시
- `TradingPanelUIController`: 수동 매매 입력
- `DailySettlementUIController`: 멀티 결과 화면의 기초

### 신규 시스템 후보

| 클래스 | 역할 |
|---|---|
| `P2PMatchManager` | 방 생성, 참가, 시작, 종료 및 전체 경기 상태 관리 |
| `SteamLobbyManager` | Steam 방 생성, 검색, 참가, 친구 초대 및 로비 소유자 관리 |
| `P2PLobbyController` | 참가자, 준비 상태, 최대 레버리지와 최대 마진 규칙 관리 |
| `SteamP2PTransport` | Steam Networking 기반 패킷 송수신 |
| `NetworkMarketAuthority` | 공통 시장 시드, 시간, 가격 동기화 |
| `NetworkTradingAuthority` | 주문 검증과 권위형 체결 처리 |
| `MultiplayerPlayerState` | 플레이어별 자산, 포지션, 체력, 멘탈과 탈락 상태 보관 |
| `P2PInventoryAuthority` | 동일 인벤토리 초기화, 아이템 구매·사용과 금지 효과 검증 |
| `P2PChoiceEventController` | 공통 이벤트 발생, 15초 제한, 무작위 선택과 결과 적용 |
| `MultiplayerLeaderboard` | 실시간 및 최종 순위 계산 |
| `P2PMatchHUDController` | 참가자 정보와 순위 HUD 표시 |
| `P2PResultUIController` | 최종 결과 및 재대결 UI |

기존 싱글톤 시스템은 한 명의 상태만 전제로 하는 부분이 많으므로, 멀티플레이에서는 `TraderStatus`와 `TradingController`의 데이터를 플레이어 식별자별로 분리하거나 호스트 전용 경기 상태 모델을 별도로 두어야 합니다.

## 9. 개발 단계 제안

### Phase 1. 로컬 멀티 시뮬레이션

- 한 프로세스에서 가상 플레이어 2~4명의 상태 생성
- 하나의 공통 시장에 독립 포지션 적용
- 순위 및 24:00 최종 정산 검증

### Phase 2. P2P 로비

- Steam 방 생성, 검색 및 참가
- Steam 친구 초대
- 초대 코드
- 참가자 목록 및 준비
- 최대 레버리지와 최대 마진 비율 설정 및 동기화
- 호스트 시작 및 씬 전환

### Phase 3. 경기 동기화

- 공통 시간과 시장 가격 동기화
- 네트워크 주문 요청 및 호스트 승인
- 플레이어별 자산과 포지션 복제
- 플레이어별 체력, 멘탈 및 탈락 상태 복제
- 파산과 멘탈 0의 호스트 권위 탈락 판정
- 아이템 구매·사용 및 인벤토리 동기화
- 공통 돌발 이벤트와 15초 선택 제한 동기화
- 실시간 순위 HUD

### Phase 4. 예외 처리

- 재접속
- 호스트 이탈
- 중복 주문 및 지연 입력 방지
- 시장 상태 불일치 자동 교정
- 비정상 클라이언트 값 차단

### Phase 5. 연출과 확장

- 전체 알림 및 역전 연출
- 경기 결과 그래프
- 재대결
- 공개방 검색
- 아이템전 및 이벤트전 규칙

## 10. MVP 완료 조건

- 1~4명이 같은 방에 참가할 수 있습니다.
- 전원이 준비하면 호스트가 경기를 시작할 수 있습니다.
- 호스트가 로비에서 최대 레버리지와 최대 마진 비율을 설정할 수 있습니다.
- 모든 참가자에게 동일한 로비 규칙이 표시되고 적용됩니다.
- 모든 참가자에게 같은 차트와 같은 인게임 시간이 표시됩니다.
- AI 자동매매와 모든 우회 강제매매가 차단됩니다.
- 플레이어별 LONG, SHORT, 청산 요청이 독립적으로 처리됩니다.
- 모든 플레이어가 동일 조건으로 캐릭터 케어 아이템을 구매하고 사용할 수 있습니다.
- 시간 가속 아이템과 스킬 업그레이드는 사용할 수 없습니다.
- 돌발 이벤트가 전원에게 동시에 표시되고 15초 안에 각자 선택할 수 있습니다.
- 미선택 플레이어에게 유효한 선택지 하나가 자동으로 무작위 배정됩니다.
- 참가자별 자산과 수익률이 실시간으로 표시됩니다.
- 24:00에 모든 포지션이 강제 청산됩니다.
- 최종 수익률에 따라 1~4위가 결정됩니다.
- 총자산 0 또는 멘탈 0에 도달한 플레이어가 즉시 탈락하고 관전 상태로 전환됩니다.
- P2P 경기에서는 오버도즈 강제매매와 보호 시간이 발생하지 않습니다.
- 파산, 연결 끊김과 중복 입력이 경기 전체를 중단시키지 않습니다.

4. 정확한 시작 자산과 경기 시간

6. 체력 소진에 별도 페널티를 추가할지 여부
7. 경기 시작 시 제공할 기본 케어 아이템의 종류와 수량
8. P2P 전용 돌발 이벤트별 공통 시장 결과와 개인 선택 효과
9. 다른 플레이어의 포지션 방향과 레버리지를 어디까지 공개할지 여부
10. 네트워크 지연에 따른 체결가 처리 정책
11. 전적, 랭크 및 보상 시스템 추가 여부

## 12. 향후 확장 아이디어

- **랭크 매치:** 승패와 수익률을 기반으로 시즌 점수 산정
- **비공개 전략전:** 상대 포지션 방향을 숨기고 자산 순위만 공개
- **오픈 포지션전:** 모든 플레이어의 방향과 레버리지를 공개
- **고위험 아이템전:** 기본 경기보다 강한 회복 및 방어 아이템 사용
- **이벤트 러시:** 공통 돌발 이벤트가 더 자주 발생하는 규칙
- **토너먼트:** 여러 방의 승자가 다음 라운드에 진출
- **리플레이:** 공통 차트 위에 각 플레이어의 진입·청산 지점 표시
- **관전자 모드:** 탈락자 또는 별도 관전자가 경기 흐름 시청
