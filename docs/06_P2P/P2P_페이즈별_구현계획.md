# FX Overdose Steam P2P 페이즈별 구현 계획
## 1. 목적

본 문서는 Steam PC판 1~4인 P2P 경쟁 모드를 위험도가 낮은 순서로 구현하기 위한 단계별 작업 계획입니다.

세부 동작과 데이터 규격은 [P2P 기능명세서](P2P_기능명세서.md), 게임 규칙은 [P2P 멀티플레이 기획서 초안](P2P_멀티플레이_기획서_초안.md)을 따릅니다.

---

## 2. 개발 원칙

1. 네트워크 연결 전에 로컬 다중 플레이어 도메인 모델을 검증합니다.
2. 기존 싱글플레이 코드를 즉시 네트워크 컴포넌트로 바꾸지 않습니다.
3. 시장, 주문과 탈락 판정은 호스트 권위로 유지합니다.
4. 각 페이즈는 독립적인 실행 데모와 완료 기준을 가져야 합니다.
5. 기능 추가 후 1인, 2인과 4인 회귀 테스트를 수행합니다.
6. 기존 STORY, ENDLESS와 CHALLENGE 동작을 보존합니다.
7. 미커밋 사용자 변경과 Unity `.meta` 파일을 임의로 되돌리지 않습니다.

## Phase 0. 기술 검증 및 기준선 확보

### 목표

실제 게임 코드를 크게 수정하기 전에 Steam과 NGO 조합의 기술 가능성을 확인합니다.

### 작업

- 현재 Unity Editor, 플랫폼과 패키지 버전 기록
- Windows x64 개발 빌드 생성 확인
- Steamworks.NET 도입 방식 결정
- NGO 버전 결정
- Steam Networking용 NGO Transport 후보 조사 및 샘플 분리 테스트
- Steamworks SDK 네이티브 파일 배치 정책 결정
- 개발용 App ID와 정식 App ID 관리 방식 정의
- 기존 CHALLENGE 모드의 수동매매, 아이템, 시간과 게임오버 회귀 테스트 기록
- Steam API를 사용할 수 없는 에디터 실행을 위한 안전한 폴백 설계

### 산출물

- 기술 결정 기록
- 패키지 및 라이선스 목록
- Steam 초기화 전용 빈 씬 또는 샘플 프로젝트
- 기존 싱글플레이 기준 테스트 결과

### 완료 기준

- Steam 클라이언트가 실행된 두 PC 또는 두 Steam 세션에서 테스트 앱이 서로를 식별합니다.
- 선택한 Transport가 현재 Unity와 NGO 버전에서 컴파일됩니다.
- Steam API 실패가 기존 싱글플레이 실행을 막지 않습니다.

## Phase 1. 로컬 멀티플레이 도메인 분리

구현 상태: `완료 (2026-08-11)`

구현 기록: [P2P Phase 1 구현 기록](P2P_Phase1_구현기록.md)

### 목표

현재 싱글톤 중심 구조에서 네트워크와 무관한 플레이어별 경기 상태를 분리합니다.

### 작업

- `P2PMatchRules` 작성
- `MultiplayerPlayerState` 작성
- 플레이어별 현금, 총자산, 포지션, 체력, 멘탈과 인벤토리 모델 작성
- 순수 C# 주문 검증기 작성
- 순수 C# 손익 및 청산 계산기 작성
- 파산과 멘탈 0 탈락 판정기 작성
- 실시간 및 최종 순위 계산기 작성
- 한 프로세스에서 가상 플레이어 4명 시뮬레이션
- 기존 `TradingController` 로직 중 재사용할 계산과 Unity 객체 의존 로직 구분

### 권장 클래스

```text
P2PMatchRules
P2PPlayerRuntimeState
P2PPositionState
P2PTradeValidator
P2PTradeCalculator
P2PEliminationEvaluator
MultiplayerLeaderboard
```

### 테스트

- 같은 가격에서 서로 다른 LONG·SHORT 포지션 손익 계산
- 최대 레버리지와 최대 마진 상한 검증
- 현금 0이지만 증거금이 남은 경우 생존
- 총자산 0 파산
- 멘탈 0 즉시 탈락
- 동일 틱 동시 탈락 순위

### 완료 기준

- 네트워크 없이 가상 플레이어 4명이 한 시장에서 독립적으로 거래합니다.
- 싱글톤 `TraderStatus`를 복제하지 않고도 4명의 상태를 계산할 수 있습니다.
- 주요 계산에 자동 테스트가 존재합니다.

## Phase 2. Steam 초기화 계층

구현 상태: `코드 완료 / Unity 라이선스 복구 후 자동 테스트 재실행 필요 (2026-08-11)`

구현 기록: [P2P Phase 2 구현 기록](P2P_Phase2_구현기록.md)

### 목표

게임이 Steam 사용자와 App ID를 안정적으로 인식하게 합니다.

### 작업

- `SteamBootstrap` 작성
- 중복 인스턴스 방지 및 `DontDestroyOnLoad` 적용
- Steam API 초기화·종료 처리
- Steam 콜백 펌프 처리
- 로컬 Steam ID와 닉네임 조회
- Steam 미실행, App ID 오류와 라이선스 오류 UI
- 개발용 `steam_appid.txt` 관리 및 배포 제외 설정
- TitleScene에 P2P 메뉴 활성·비활성 상태 연동

### 테스트

- Steam 실행 상태에서 초기화 성공
- Steam 미실행 상태에서 안전한 실패
- 씬 전환 후 중복 Bootstrap 미생성
- 게임 종료 시 예외 없는 Shutdown

### 완료 기준

- 타이틀 화면에서 Steam 닉네임과 ID를 확인할 수 있습니다.
- Steam 초기화 실패 시 STORY 등 오프라인 기능은 유지되고 P2P만 비활성화됩니다.

## Phase 3. Steam 로비

구현 상태: `서비스 코드 완료 / Unity 테스트 및 다중 Steam 세션 검증 필요 (2026-08-11)`

- `SteamLobbyManager` 작성
- 공개, 친구 전용과 비공개 로비 생성
- 로비 목록 검색 및 필터
- 친구 초대 Overlay
- 초대 수락 및 게임 실행 후 로비 참가
- 로비 참가자 카드
- 호스트 표시
- 준비 상태
- 최대 레버리지 프리셋
- 최대 마진 비율 프리셋
- 규칙 변경 시 준비 해제
- 빌드 버전과 모드 Lobby Data 검증

### 테스트

- 2~4인 참가 및 퇴장
- 친구 초대 수락
- 정원 초과 거절
- 다른 빌드 버전 거절
- 비호스트 규칙 변경 차단
- 규칙 변경 시 준비 상태 초기화

### 완료 기준

- 네 명이 같은 로비에 입장하고 동일한 규칙과 준비 상태를 확인합니다.
- 방장만 경기 설정과 시작을 제어합니다.

## Phase 4. NGO와 Steam Transport 연결

구현 상태: `연결 계층 코드 완료 / Unity 임포트 및 2~4인 실기기 검증 필요 (2026-08-11)`

구현 기록: [P2P Phase 4 구현 기록](P2P_Phase4_구현기록.md)

### 목표

Steam Lobby 참가자를 실제 NGO 호스트와 클라이언트 연결로 전환합니다.

### 작업

- `NetworkManager` 구성
- Steam Transport 설치 또는 `SteamP2PTransport` 작성
- Steam ID 기반 목적지 연결
- Connection Approval Payload 작성
- Steam ID와 NGO Client ID 매핑
- Lobby ID, Nonce와 Build Version 검증
- 연결, 거절과 종료 콜백 처리
- LoadingScene에서 연결 준비 상태 표시
- Network Prefab 등록 규칙 정리

### 테스트

- 2인 호스트·클라이언트 연결
- 4인 동시 연결
- 중복 Steam ID 거절
- 잘못된 Lobby ID 거절
- 호스트가 시작하기 전 클라이언트 준비 확인
- 클라이언트 종료 후 연결 정리

### 완료 기준

- Steam 로비의 모든 참가자가 올바른 NGO Client ID를 받습니다.
- 잘못된 연결 요청이 경기 객체를 생성하지 못합니다.

## Phase 9. 공통 돌발 선택 이벤트

### 목표

모든 생존자에게 동시에 이벤트를 표시하고 15초 안에 각자 선택하게 합니다.

### 작업

- P2P 전용 이벤트 데이터 구조 작성
- 기존 15종 이벤트의 공통 시장 효과와 개인 효과 분리
- `P2PChoiceEventController` 작성
- 호스트 이벤트 발생 스케줄
- 이벤트 중 공통 시장 정지
- 서버 기준 15초 Deadline
- 플레이어별 선택 제출 및 잠금
- 요구 아이템 검증
- 전원 조기 선택 시 즉시 진행
- 시간 초과 결정적 무작위 선택
- 공통 시장 결과 적용
- 플레이어별 포지션·체력·멘탈·아이템 결과 적용
- 이벤트 결과 탈락 판정
- 선택 완료 여부 및 결과 UI

### 테스트

- 4명 모두 서로 다른 선택
- 전원 조기 선택
- 한 명 미선택 자동 배정
- 아이템 부족 옵션 무작위 제외
- 이벤트 도중 연결 종료
- 이벤트 결과로 멘탈 0
- 이벤트 결과로 파산
- 두 이벤트 중복 발생 차단

### 완료 기준

- 모든 생존자에게 동일 이벤트와 Deadline이 표시됩니다.
- 15초 이후 미선택자가 남지 않습니다.
- 모든 플레이어는 하나의 공통 시장 결과를 공유합니다.

## Phase 10. 정산, 결과 및 재대결

### 목표

24:00 또는 마지막 생존자 발생 시 결과를 확정하고 로비로 복귀합니다.

### 작업

- 신규 주문 차단
- 열린 포지션 일괄 종료
- 최종 수익률과 동률 규칙
- 탈락자 순위
- 경기 통계 수집
- `P2PResultUIController` 작성
- 플레이어별 자산 곡선
- 최고 자산, 최대 낙폭과 청산 횟수
- 탈락 사유 표시
- 재대결 준비 초기화
- 로비 복귀

### 테스트

- 정상 24:00 종료
- 마지막 생존자 조기 종료
- 완전 동률
- 전원 동시 탈락
- 결과 중 중복 종료 호출
- 재대결 후 이전 상태 잔존 여부

### 완료 기준

- 모든 참가자에게 같은 최종 순위와 통계가 표시됩니다.
- 재대결 시 시장, 자산, 인벤토리와 탈락 상태가 완전히 초기화됩니다.

## Phase 11. 연결 예외, 보안 및 최적화

### 목표

실제 네트워크 환경에서 한 명의 오류가 전체 경기를 망치지 않게 합니다.

### 작업

- 클라이언트 재접속 유예
- 재접속 스냅샷 복원
- 재접속 실패 기권
- 로비 단계 호스트 소유권 이전
- 경기 단계 호스트 이탈 무효 처리
- 주문 Rate Limit
- 비정상 패킷 카운트 및 차단
- Sequence와 Request ID Wrap-around 검토
- 네트워크 전송량 측정
- 반복 패킷 GC 할당 제거
- 낮은 FPS와 높은 핑 테스트
- 로그 및 Match ID 추가

### 테스트 환경

- 50ms, 100ms, 200ms 지연
- 패킷 유실
- 클라이언트 강제 종료
- Steam Overlay 중단
- 네트워크 순간 단절
- 호스트 강제 종료
- 잘못된 레버리지·마진·아이템 패킷 반복

### 완료 기준

- 클라이언트 한 명의 종료가 다른 참가자의 프로세스를 중단시키지 않습니다.
- 상태 불일치가 전체 스냅샷으로 복구됩니다.
- 비정상 요청이 권위 상태를 변경하지 못합니다.

## Phase 12. Steam 출시 준비

### 목표

Steam 빌드에서 멀티플레이를 반복 검증하고 배포 준비를 마칩니다.

### 작업

- 정식 App ID 적용
- `steam_appid.txt` 배포 제외 확인
- Steam 네이티브 라이브러리 빌드 포함 확인
- Steam Depot 설치 테스트
- Overlay 친구 초대 테스트
- 서로 다른 네트워크 환경 테스트
- 최소·권장 사양 테스트
- 개인정보 및 로그 검토
- 오픈소스 라이선스 고지
- 네트워크 오류 문구 현지화
- P2P 사용자 가이드 작성
- 알려진 문제와 지원 절차 작성

### 출시 전 필수 시나리오

- 1인 연습방 완주
- 2인 친구 초대 경기 완주
- 4인 공개방 경기 완주
- 파산 탈락
- 멘탈 0 탈락
- 아이템 구매 및 사용
- 파스타 및 스킬 업그레이드 차단
- 돌발 이벤트 조기 선택
- 돌발 이벤트 시간 초과 무작위 선택
- 클라이언트 연결 종료
- 호스트 연결 종료
- 24:00 정산 및 재대결

### 완료 기준

- Steam 설치 빌드끼리 주요 시나리오가 재현 가능하게 통과합니다.
- 치명적인 동기화 오류와 진행 불가 문제가 없습니다.
- P2P 기능을 비활성화해도 기존 싱글플레이 모드가 정상 동작합니다.

## 4. 권장 첫 번째 구현 마일스톤

첫 번째 실제 마일스톤은 아래 범위까지만 진행하는 것을 권장합니다.

```text
Phase 0 기술 검증
  + Phase 1 로컬 4인 상태 모델
  + Phase 2 Steam 초기화
  + Phase 3 Steam 2인 로비
  + Phase 4 빈 씬 NGO 연결
```

이 단계에서는 실제 차트와 매매를 네트워크에 연결하지 않습니다. 두 Steam 사용자가 로비에 들어와 NGO 호스트·클라이언트 연결을 완료하고 서로의 Steam ID와 준비 상태를 확인하는 것을 첫 번째 성공 기준으로 삼습니다.
