# P2P Phase 7~10 구현 기록

구현일: 2026-08-12

## 결과

Phase 7부터 Phase 10까지 호스트 권위 경기 흐름과 `GameScene` 플레이 UI를 연결했습니다.

## Phase 7 — 체력·멘탈·탈락

- 호스트가 체력과 멘탈을 주기적으로 계산하고 전원에게 복제합니다.
- 미실현 손실이 커질수록 멘탈 소모가 증가합니다.
- 총자산 0 이하 파산 또는 멘탈 0에서 탈락합니다.
- 탈락 전에 열린 포지션을 호스트 가격으로 정리하고 주문을 차단합니다.
- 탈락 플레이어는 경기 화면과 순위를 유지한 채 관전 상태로 전환합니다.
- 2인 이상 경기에서 생존자가 한 명이면 조기 종료합니다.

## Phase 8 — 케어 아이템

- 기존 챌린지 구성처럼 전원에게 에너지 드링크·파르페 5개와 진정제·영양제 2개를 동일하게 지급합니다.
- 호스트가 구매 비용, 보유 수량과 회복 효과를 검증합니다.
- 허용 아이템은 에너지 드링크, 파르페, 진정제와 영양제이며 기존 가격과 회복량을 사용합니다.
- 배달음식과 액티브 기어는 호스트 허용 목록에 존재하지 않아 표시·구매·사용할 수 없습니다.
- 경기 인벤토리는 세이브 데이터와 분리된 일회성 상태입니다.

## Phase 9 — 15초 공통 돌발 이벤트

- 12:00과 18:00에 모든 참가자에게 같은 이벤트를 엽니다.
- 이벤트 중 시장과 매매를 정지하고 실제 시간 15초를 제공합니다.
- 원본 이벤트의 일반 1안·2안만 표시하며 아이템을 소모하는 3안은 P2P에서 제외합니다.
- 시간 내 선택하지 않으면 Steam ID와 이벤트 번호를 바탕으로 1안·2안 중 하나를 결정적으로 무작위 배정합니다.
- 모든 효과와 후속 탈락은 호스트가 판정합니다.

## Phase 10 — 정산·결과

- 24:00 또는 최후 생존자 조건에서 경기를 종료합니다.
- 모든 포지션을 호스트 가격으로 정리한 뒤 최종 자산 순위를 확정합니다.
- 결과 화면에서 최종 리더보드를 확인하고 로비에서 나갈 수 있습니다.

## 실제 플레이 화면

`P2PGameplayUIController`가 NGO의 `GameScene` 동기화 완료 후 기존 `TradingViewCanvas`를 그대로 재사용합니다. 기존 차트, 상단 상태바, 거래 패널, 캐릭터 영역과 인벤토리 외형은 유지하고 표시 데이터와 버튼 입력만 P2P 권위 상태에 연결합니다.

싱글플레이 시장, 자동 투자와 시간 가속·스킬 로직은 P2P 경기 동안 비활성화됩니다. 기존 캔들 차트 렌더러, 상단 HUD, 거래 패널, 인벤토리와 상점 UI를 그대로 재사용하며 데이터와 입력만 P2P 권위 계층에 연결합니다. 인벤토리와 상점에는 원래 에너지 드링크·파르페·진정제·영양제만 표시하고 배달음식·액티브 기어는 제외합니다. 별도로 추가하는 인게임 UI는 전체 플레이어 P&L 패널뿐입니다.

Steam 로비의 최소 인원은 1명이며 호스트는 별도 준비 입력 없이 준비된 것으로 처리되므로, 기능 확인을 위한 1인 경기 시작도 지원합니다.

## 기술 스택

- Unity 6: 씬, 런타임 UI와 게임 루프를 실행하는 게임 엔진입니다.
- Netcode for GameObjects 2.7.0: 호스트·클라이언트 연결, 씬 동기화와 사용자 정의 메시지 전송을 담당하는 Unity 네트워크 프레임워크입니다.
- Steamworks.NET: Steam 사용자 ID와 로비 정보를 C#에서 사용하는 Steamworks 래퍼입니다.
- Steam Networking Sockets Transport: NGO 패킷을 Steam P2P 연결로 전달하는 전송 계층입니다.
- 호스트 권위 구조: 시장, 주문, 아이템, 이벤트와 탈락을 호스트만 확정하여 클라이언트 조작과 상태 불일치를 줄입니다.
- BinaryWriter/Reader 바이너리 코덱: 네트워크 상태를 작고 명확한 바이트 배열로 직렬화합니다.
- TextMeshPro 및 uGUI: 실제 경기 HUD, 버튼, 이벤트 모달과 결과 화면을 런타임에 구성합니다.
- NUnit EditMode Test: Unity 실행 없이 코덱과 정산 규칙을 반복 검증합니다.
