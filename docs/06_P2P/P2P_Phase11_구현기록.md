# P2P Phase 11 구현 기록

구현일: 2026-08-14

## 결과

연결 예외와 비정상 요청이 다른 참가자의 경기를 즉시 중단시키거나 권위 상태를 오염시키지 않도록 방어 계층을 추가했습니다.

## 재접속과 호스트 이탈

- 클라이언트 연결 종료 시 즉시 탈락시키지 않고 15초 유예 상태로 전환합니다.
- 유예 중에는 기존 포지션 손익과 HP·멘탈 자연 감소를 호스트가 계속 계산합니다.
- 연결이 끊긴 Steam ID의 신규 주문·아이템·이벤트 선택은 차단합니다.
- 클라이언트는 2초 간격으로 최대 3회 자동 재접속을 시도합니다.
- 같은 Steam ID가 돌아오면 기존 런타임 상태를 다시 연결하고 시장·거래·경쟁 전체 스냅샷을 전송합니다.
- 유예 시간 종료 시 열린 포지션을 정리하고 `DisconnectForfeit`로 탈락시킵니다.
- 호스트에 재접속하지 못하면 `MATCH INVALID` 결과 화면을 표시하고 경기 결과를 무효 처리합니다.
- 로비 단계 소유권은 Steam Lobby의 새 Owner 스냅샷을 그대로 따르며, 경기 중에는 새 호스트를 만들지 않습니다.

## 요청 보안

- 거래 요청은 플레이어당 초당 8회, 아이템·이벤트 요청은 초당 6회로 제한합니다.
- 잘못된 Steam ID, 해석할 수 없는 Payload, 범위 밖 레버리지·마진 요청을 위반으로 기록합니다.
- 위반이 6회 누적되면 해당 NGO 클라이언트 연결을 종료합니다.
- 호스트가 승인한 마지막 Request ID만 보관하여 중복 요청을 차단하고 무한히 커지는 `HashSet`을 제거했습니다.
- 부호 없는 정수의 serial number 비교를 사용하여 Request ID와 상태 Sequence의 wrap-around를 처리합니다.

## 상태 복구와 진단

- 거래 상태에 64비트 Sequence를 추가하여 늦게 도착한 Unreliable 패킷이 최신 PnL을 덮어쓰지 못하게 했습니다.
- 시장·거래·경쟁 상태 모두 오래된 Sequence를 폐기합니다.
- Lobby ID와 Connection Nonce 일부로 민감 정보가 없는 Match ID를 생성합니다.
- 주문 승인·거절, 보안 차단, 재접속과 경기 무효 로그에 Match ID를 포함합니다.
- 10초마다 송수신 바이트/초와 패킷 수를 `[P2P NetStats]` 로그로 출력합니다.

## 기술 스택

- NGO Custom Messaging: 시장·주문·경쟁 스냅샷을 전달합니다.
- Steam Networking Sockets: Steam Relay 기반 연결과 재접속 대상을 제공합니다.
- 호스트 권위 상태: 연결이 끊겨도 호스트가 포지션과 생존 상태를 유지합니다.
- Sliding Window Rate Limit: 1초 요청 창을 기준으로 과도한 입력을 제한합니다.
- Serial Number Arithmetic: uint/ulong 최대값을 넘어간 요청과 상태 순서를 안전하게 비교합니다.
- NUnit EditMode Test: Rate Limit, 재접속 상태 보존과 Request ID wrap-around를 검증합니다.

## 검증 상태

- `git diff --check` 통과
- Rate Limit 단위 테스트 추가
- 재접속 중 주문 차단 및 상태 복구 테스트 추가
- Request ID wrap-around 테스트 추가
- 거래 상태 Codec Sequence 왕복 테스트 추가
- 로컬 환경에 `dotnet` 실행 파일이 없어 CLI 테스트는 실행하지 못했습니다.
- Unity Test Runner와 2대의 Steam 클라이언트에서 지연·패킷 유실·강제 종료 실기기 검증이 필요합니다.

## 실기기 확인 항목

1. 클라이언트 네트워크를 5초 끊었다 복구했을 때 동일 자산·포지션으로 복귀하는지 확인합니다.
2. 15초 이상 복구하지 않았을 때 해당 플레이어만 기권되는지 확인합니다.
3. 호스트를 종료했을 때 클라이언트에 `MATCH INVALID`가 표시되는지 확인합니다.
4. 버튼 연타 또는 변조 패킷이 권위 상태를 변경하지 않는지 확인합니다.
5. 50/100/200ms 지연과 패킷 유실에서 PnL이 과거 값으로 되돌아가지 않는지 확인합니다.
6. `[P2P NetStats]`의 전송량과 GC Alloc을 Unity Profiler에서 함께 확인합니다.
