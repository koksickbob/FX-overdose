# 요미의 방 — 배치 재검토 v01

상태: **사용자 확인을 위한 제안. 후속 일러스트 제작은 배치 확인 후 진행한다.**

- 배경: 사용자 채택 완료한 [B1 아침 v02](B1_Morning_v02.png).
- 사용자 확인: 탁자는 **핸드폰·꽃병용 하나**로 통합한다.
- [배치 검토 이미지](Layout_v01.png) · [가구·요미·꽃병·UI를 켜고 끄는 검토 화면](Layout_v01.html)
- 검토 화면은 기존 이미지와 코드로 그린 배치 가이드를 합성한 설명용 화면이다. 새로운 가구 일러스트를 생성한 것이 아니다.

## 1. 결론

**현재 문 시안을 그대로 사용하면 간섭을 피하기 어렵다. 오른쪽 뒤쪽의 문이라는 방향은 유지하고, 문 크기와 침대 위치를 함께 조정한다.**

권장 구역은 왼쪽 책상·컴퓨터 / 중앙 요미 / 오른쪽 뒤 공용 탁자와 문 / 오른쪽 앞 침대다. 문 아래와 탁자 위를 먼저 비워 두면 침대와 추후 꽃병이 늘어나도 출입구와 클릭 대상이 묻히는 일을 줄일 수 있다.

## 2. 기존 안에서 확인한 문제

1. 명세의 문 범위 `x1400~1580, y150~700`과 침대 범위 `x1250~1920, y620~1080`는 가로 180px × 세로 80px가 겹친다. 이는 가이드 사각형의 겹침이며 실제 실루엣끼리 반드시 충돌한다는 뜻은 아니지만, 문 하부를 침대가 가릴 여지가 있다.
2. 기존 탁자 범위와 침대 범위도 가로 140px × 세로 60px가 겹친다. 이후 꽃병까지 올릴 때를 고려한 탁자 상부 공간은 따로 정의되어 있지 않았다.
3. 생성된 [문 v01](O4_Door_v01.png)은 문 자체가 명세보다 크게 그려졌다. 1920×1080으로 환산한 육안 범위가 대략 `x1340~1645, y74~952`라서 기존 침대와 탁자 자리를 크게 침범한다. 해당 시안은 보류한다.
4. 채택한 배경의 뒷벽 오른쪽 모서리는 가로 약 75% 지점이다. 명세 좌표만 따를 경우 문 일부가 뒷벽과 오른쪽 벽에 걸칠 수 있다. 실제 채택 배경의 벽 경계를 우선한다.

## 3. 제안 좌표

모든 좌표는 **1920×1080, 왼쪽 위 원점**으로 환산했다. 채택된 1672×941 배경의 파일은 변경하지 않고 검토 화면에서 같은 비율로 표시했다.

| 요소 | 제안 범위 | 배치 의도 |
| --- | --- | --- |
| 요미 원본 | x770~1150, y180~940 | 현재 런타임 빌더의 배치와 동일. 중앙 고정 |
| 요미 예약 공간 | x700~1220, y160~1080 | 가구와 꽃이 이 안에 들어오지 않도록 여유 확보 |
| 컴퓨터·L자 책상·의자 | x50~660, y435~1030 | 왼쪽 벽을 따라 배치. 의자까지 x660 이내 |
| 모니터 핵심부 | x335~650, y435~680 | 좌상단 상태 카드 x0~300을 피해 차트가 읽히게 배치 |
| 핸드폰·꽃병용 탁자 | x1250~1420, y540~720 | 창문 오른쪽 아래와 문 왼쪽 사이. 핸드폰은 탁자에 포함 |
| 꽃병과 꽃 확장 공간 | x1260~1420, y370~540 | 탁자 상판 위에 미리 예약. 꽃가지도 이 범위 안으로 제한 |
| 문 전체 | x1450~1595, y144~694 | 오른쪽 측벽 뒤쪽. 문틀·손잡이·경첩도 모두 이 범위 안 |
| 침대 전체 | x1280~1920, y760~1080 | 머리맡을 카메라 쪽으로 당기고 발치·오른쪽 일부 잘림 허용 |

문 바깥 네 꼭짓점의 초기 가이드는 `(1450,180) → (1595,144) → (1595,694) → (1450,604)`다. 문 위·아래 깊이 방향의 기울기는 소실점 `(960,300)` 근처로 수렴하도록 잡았다. 문틀의 실제 접지와 세부 원근은 최종 레이어 합성에서 다시 확인한다.

### 범위 검산

제안한 문·탁자·꽃병·컴퓨터·침대와 요미 예약 공간의 사각형을 쌍별 비교했을 때 **면적이 겹치는 조합은 0개**다.

- 문 하단 y694 → 침대 최상단 y760: **66px 여유**.
- 탁자/꽃병 오른쪽 x1420 → 문 왼쪽 x1450: **30px 여유**.
- 컴퓨터/의자 오른쪽 x660 → 요미 예약 공간 왼쪽 x700: **40px 여유**.
- 요미 예약 공간 오른쪽 x1220 → 탁자 왼쪽 x1250: **30px 여유**.
- 꽃병 영역의 아래 경계와 탁자 영역의 위 경계는 y540에서 맞닿는다. 같은 세트의 상판과 장식품 접점이다.

이는 **제안한 영역의 검산**이다. 아직 없는 가구의 실제 알파 실루엣, 손잡이의 클릭 면적, 다른 화면 비율에서의 잘림까지 통과했다는 의미는 아니다.

## 4. 위에서 본 구조

[검토 화면](Layout_v01.html) 아래쪽에 평면 배치 개념도를 넣었다.

- 3.6m × 4m의 방, 싱글 침대 1m × 2m, 공용 탁자 약 0.7m × 0.5m를 가정했다.
- 탁자는 뒷벽 쪽에, 침대는 오른쪽 앞쪽에 둔다. 둘 사이의 오른쪽 벽을 문 자리로 남긴다.
- **문은 바깥으로 열리는 현관문으로 제안한다.** 방 안으로 문짝이 회전하면서 침대 머리맡이나 탁자에 닿는 상황을 피한다. 문 열림 방향은 아직 사용자가 확정하지 않았다.
- 문 안쪽에 약 0.8m 깊이의 빈 공간을 잡고, 방 중앙에서 그곳으로 접근하는 통로를 남긴다.
- 이 평면도는 가구와 출입 공간의 관계를 검토하는 개념도다. 채택한 배경의 카메라와 건축 치수를 정밀하게 맞춘 실측 도면이 아니다.

## 5. 클릭과 UI

현재 [런타임 빌더](../../../Assets/Scripts/DatingSim/UI/YomiRoomPointClickBuilder.cs)는 배경 → 문 → 핸드폰 → 컴퓨터 → 침대 → 요미 순서로 그린다. 따라서 침대가 문과 겹치면 침대가 앞에 보이며, 알파가 있는 영역에서 클릭도 가져갈 수 있다.

- 가구 전체를 중앙 예약 영역 밖에 두어 요미의 몸·머리카락에 가려지지 않게 한다.
- 모니터 화면은 좌상단 상태 카드 아래에 숨지 않도록 별도 핵심 영역을 지정했다.
- 대화 패널을 열면 오른쪽 문·탁자·침대가 가려지는 것은 현재 설계대로다. 패널이 열린 동안 뒤 오브젝트 입력은 차단한다.
- 탁자와 꽃병은 시각적으로 하나의 세트지만, 향후 꽃병에 독립 클릭을 줄지는 별도 결정 사항이다. 현재 제작 범위는 핸드폰을 포함한 탁자 하나다.
- 최종 이미지가 들어오면 전 화면 크기로 겹쳐지는 구조이므로, 실제 이미지 내부 위치가 중요하다. 플레이스홀더 좌표만 바꾸어서는 최종 스프라이트 위치가 바뀌지 않는다.

## 6. 다음 작업

1. 이 배치 구조를 확인받는다.
2. 문 한 장의 크기·원근·알파를 이 기준으로 맞춘 뒤 컨펌을 받는다.
3. 같은 배경과 좌표 기준으로 공용 탁자 → 컴퓨터·책상 → 침대를 한 장씩 제작한다.
4. 실제 가구 레이어를 모두 겹쳐 꽃병 확장 공간, 출입구, UI, 알파 클릭과 화면 비율을 검수한다.

문 v01은 RGB 체크무늬 파일이라 사용 가능한 투명 레이어가 아니다. 일반 이미지 후처리 사용 여부는 아직 승인받지 않았다.
