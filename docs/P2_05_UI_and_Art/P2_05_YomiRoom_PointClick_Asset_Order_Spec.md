화풍은 **3/4 탑다운 픽셀아트**다. 바닥은 위에서 내려다보고 가구의 윗면이 주로 보인다. 외곽선은 1~2px 짙은 네이비로 두르고, 채색은 단계 수를 적게 둔 도트 방식이다.

### 1.2 분위기

**키워드**: 새벽 · 고립 · 모니터 불빛 · 어질러진 생활감 · 아늑하지만 건강하지 않음

- **어둡다.** 화면의 약 70%가 명도 15% 이하의 어둠이다. 방 모서리와 벽은 거의 검정에 가깝고, 빛은 몇 개의 광원 주변에만 고인다.
- **빛이 방을 채우지 않고 웅덩이로 떨어진다.** 창문으로 들어온 빛과 책상 스탠드 빛이 방 중앙 바닥에 **주황색 빛 웅덩이**를 만들고, 바깥쪽으로 갈수록 어둠에 잠긴다(강한 비네팅).
- **트레이더의 방이다.** 모니터 5대가 L자 책상을 둘러싸고 차트를 띄우고 있다. 방에서 가장 채도 높은 색이 모니터의 시안이다.
- **폐인 같은 생활감.** 바닥에 굴러다니는 에너지 드링크 캔(파란 캔에 노란 번개), 널브러진 잡지, 구겨진 휴지 뭉치, 책상 위 헤드폰. 청소를 오래 안 한 방이지만 더럽다기보다 **"한 사람이 여기서만 지낸다"**는 인상이다.
- **창밖은 멀다.** 블라인드 너머로 밝은 도시 스카이라인이 보이지만, 그 빛은 창틀 근처까지만 닿는다. 바깥 세상과 방 안의 거리감이 분위기의 핵심이다.
- 창가 화분 하나와 스탠드 불빛이 유일하게 따뜻한 온기를 준다.

### 1.3 색 구조 — 난색 빛 vs 한색 그림자

현행 방은 **난색(주황·앰버) 광원**과 **한색(네이비·시안·보라) 그림자·소품**의 보색 대비로 짜여 있다.

| 계열 | 역할 | 대표 요소 |
| --- | --- | --- |
| 난색 | 빛, 온기, 나무 | 바닥 빛 웅덩이, 책상 상판, 스탠드, 창빛 |
| 한색 | 어둠, 벽, 기계, 침구 | 벽, 모니터, 침대 프레임, 담요, 문 |

채도는 **광원만 높고 나머지는 중~저채도**다. 원색은 모니터의 시안·핑크 캔들, 스탠드의 앰버, 캔의 노란 번개에만 쓰인다.

## 2. 신규 스타일 방향

### 2.1 ⚠️ 화풍 — 발주 전 확정 필요

현행 방은 **저해상도 탑다운 픽셀아트**다. 새 씬 중앙에 서는 요미 `T1/Calm`은 **고해상도 애니메이션풍 셀 일러스트**(깔끔한 선화, 부드러운 명암)다. 둘을 한 화면에 겹치면 화풍 차이가 바로 드러난다.

| 안 | 내용 | 판단 |
| --- | --- | --- |
| **A (권장)** | **애니메이션 배경 일러스트** (셀 + 브러시 채색). 색·분위기·소품은 §1을 그대로 계승하고, 도트 표현만 버린다 | 요미 일러스트와 화풍이 맞는다. 원근 표현이 자연스럽다 |
| B | 1920×1080 고해상도 픽셀아트 배경 | 기존 방·편의점과 화풍이 이어진다. 대신 요미 일러스트와는 분명히 따로 논다 |

**이 명세서의 이하 내용은 A안 기준으로 썼다.** B안으로 가면 §8의 Filter Mode만 `Point`로 바꾸면 되고 나머지 규격은 같다.

## 3. 해상도 통일 규정

> **요미 `T1/Calm`을 제외한 모든 에셋은 아래 규격을 예외 없이 따른다.**

| 항목 | 값 |
| --- | --- |
| 캔버스 크기 | **1920 × 1080 px** (16:9) — 모든 배경·오브젝트·호버·변형 레이어 동일 |
| 원점 | 모든 레이어가 **같은 좌표계**. PSD의 한 캔버스에서 그린 레이어를 그대로 내보낸다 |
| 트리밍 | **금지.** 오브젝트 주변 투명 영역을 잘라내지 않는다. 잘라내면 배치 좌표가 틀어진다 |
| 포맷 | PNG, RGBA 8bit, sRGB |
| 배경 | 불투명 (알파 전부 255) |
| 오브젝트 레이어 | 오브젝트 픽셀 외에는 **알파 0** (§7.2) |
| 원본 보관 | **3840 × 2160 PSD**로 작업·보관을 권장한다. 납품 PNG는 그 절반으로 축소한 1920×1080이다. 나중에 고해상도가 필요해지면 재출력한다 |

**1920×1080으로 정한 이유**
- 게임 UI 기준 해상도(`CanvasScaler.referenceResolution`)가 1920×1080이다. 1:1로 매핑된다.
- 오브젝트 레이어는 클릭 판정 때문에 CPU에서 읽을 수 있게(Read/Write) 임포트해야 해서, 같은 텍스처가 메모리에 두 벌 올라간다. 4K 레이어 4장이면 250MB를 넘기 때문에 납품 해상도는 1080p로 제한한다.
- 레이어가 모두 같은 크기이므로 코드는 전부 화면 크기로 겹쳐 늘리기만 하면 된다. 좌표 입력 작업이 없다.

## 4. 원근 구조 — 2D로 그리는 3D 공간

### 4.1 투시 규격

| 항목 | 값 |
| --- | --- |
| 투시 | **1점 투시 (정면)** — 카메라는 방 입구 쪽에서 뒷벽을 정면으로 바라본다 |
| 소실점 (VP) | **(960, 300)** — 화면 가로 중앙, 위에서 300px |
| 수평선(눈높이) | y = 300 |
| 카메라 눈높이 | 약 **1.35m** (요미의 어깨 높이). 요미를 살짝 올려다보지도 내려다보지도 않는 시선 |
| 렌즈감 | 표준 (35mm 환산 약 28~35mm). 광각 왜곡으로 가장자리가 늘어나 보이지 않게 한다 |
| 방 실제 크기 | 폭 약 3.6m · 천장 2.4m · 깊이 약 4m (원룸 한 칸) |

좌표는 모두 **1920×1080 캔버스, 왼쪽 위 원점** 기준이다.

### 4.2 공간 골격 (가이드 좌표)

```
 x=0                     446        960       1474                    1920
 y=0  ┌───────────────────╲──── 천장 ────╱───────────────────────────┐
      │                    ╲            ╱                             │
 y=51 │        왼쪽 벽      ┌────────────┐       오른쪽 벽            │
      │                     │            │                            │
 y=300│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │─ ─ ─VP─ ─ ─│─ ─ ─ ─ ─ ─ ─ ─ ─ 수평선 ─ │
      │                     │   뒷벽     │                            │
 y=620│                     └────────────┘                            │
      │                   ╱   x 533~1387   ╲                          │
      │                 ╱                    ╲                        │
      │               ╱        바닥            ╲                      │
 y=1019──────────────╱                            ╲────────────────────│
 y=1080└──────────────────────────────────────────────────────────────┘
```

| 골격 | 좌표 |
| --- | --- |
| 뒷벽 | x 533 ~ 1387, y 51 ~ 620 (가로 854 × 세로 569) |
| 바닥–왼쪽 벽 경계선 | (533, 620) → 화면 왼쪽 끝 (0, 1019) |
| 바닥–오른쪽 벽 경계선 | (1387, 620) → 화면 오른쪽 끝 (1920, 1019) |
| 천장–왼쪽 벽 경계선 | (533, 51) → 화면 위 끝 (446, 0) |
| 천장–오른쪽 벽 경계선 | (1387, 51) → 화면 위 끝 (1474, 0) |
| 스케일 기준 | 뒷벽 면 **약 237px = 1m** · 요미 서는 위치 **약 475px = 1m** (카메라와 뒷벽 사이 중간 지점) |

> 모든 사선(바닥 널판 이음새, 책상 모서리, 침대 옆선, 창틀 깊이, 문틀 깊이)은 **VP (960, 300)으로 수렴**해야 한다. 가구마다 소실점이 다르면 3D 공간감이 즉시 무너진다.
> 골격 좌표는 가이드다. 구도상 필요하면 **±40px** 안에서 조정할 수 있다. 다만 VP와 요미 영역(§4.4)은 고정이다.

### 4.3 오브젝트 배치

| 레이어 | 위치 | 가이드 영역 (x, y) | 실제 크기감 | 구도 지시 |
| --- | --- | --- | --- | --- |
| **컴퓨터** | 왼쪽 벽 | x 60 ~ 600, y 380 ~ 920 | L자 책상 폭 1.6m | 책상은 왼쪽 벽을 따라 앞뒤로 길게 놓이고, 모니터 5대가 방 안쪽을 향한다. 화면이 옆으로 비껴 보여도 **차트의 시안 빛이 읽혀야 한다**. 의자는 책상 앞, 방 안쪽으로 반쯤 돌려 둔다. 헤드폰·키보드·마우스·본체(주황 LED)는 이 레이어에 포함 |
| **문** | 오른쪽 벽 안쪽 (뒷벽 모서리 가까이) | x 1400 ~ 1580, y 150 ~ 700 | 0.9m × 2.0m | 벽면을 따라 원근으로 좁아진 문. 황동 손잡이는 방 안쪽(화면 왼쪽)에 둔다. 도어뷰 포함 |
| **핸드폰** | 뒷벽 오른쪽 모서리 앞 협탁 | x 1230 ~ 1390, y 480 ~ 680 | 협탁 0.5m | **협탁 + 폰 한 세트.** 폰 화면의 시안 충전 아이콘이 어둠 속 작은 점처럼 빛나 눈에 띄어야 한다(작은 클릭 대상을 찾기 쉽게) |
| **침대** | 오른쪽 벽 앞쪽 | x 1250 ~ 1920, y 620 ~ 1080 | 싱글 1.0m × 2.0m | 머리맡은 협탁 쪽(안쪽), 발치는 카메라 쪽. 화면 오른쪽 아래로 잘려 나가도 된다 |
| (배경) 창문 | 뒷벽 중앙 | x 700 ~ 1220, y 130 ~ 460 | 1.8m | **클릭 대상 아님.** 요미 뒤에서 역광을 만든다. 블라인드·커튼·창가 화분·스탠드 포함 |
| (배경) 소품 | 바닥 곳곳 | — | — | 캔·잡지·휴지. **요미 발밑 영역(§4.4)에는 두지 않는다** |

**앞뒤 순서 (뒤 → 앞)**: 배경 → 문 → 핸드폰 → 컴퓨터 → 침대 → 요미

- 오브젝트끼리 겹치는 부분은 **앞 레이어가 가린다.** 뒤 레이어에서는 가려지는 부분을 **지워서** 그린다. 반투명으로 비치게 두지 않는다.
- 겹치는 곳에서는 앞 레이어가 클릭을 가져간다. 한 오브젝트가 다른 오브젝트에 **절반 넘게 가려지지 않도록** 배치한다.
- 오브젝트 하나의 불투명 영역은 **최소 120×120px** 이상 (핸드폰 협탁 포함).

### 4.4 고정 영역 (배치 금지·주의)

| 영역 | 좌표 | 규칙 |
| --- | --- | --- |
| **요미 영역** | x 700 ~ 1220, y 160 ~ 1080 | 요미가 서는 자리. **오브젝트 레이어 픽셀 금지.** 배경은 그려도 되지만 요미 발밑(y 880~960)에 러그 경계선이나 소품을 두지 않는다 |
| 요미 발 위치 | 발바닥 y ≈ **940**, 가로 중앙 x = 960 | 요미 키 1.6m = 약 760px (정수리 y ≈ 180). 바닥 원근이 이 높이와 맞아야 요미가 공중에 뜨거나 파묻혀 보이지 않는다 |
| 상태 카드 UI | x 0 ~ 300, y 0 ~ 560 | 체력·시간·호감도·집착 카드가 올라간다. 벽·천장·창빛 정도만 두고, **클릭 대상의 핵심부(모니터 화면 등)를 두지 않는다** |
| 대화 패널 UI | x 1220 ~ 1920, y 120 ~ 1000 (핸드폰을 누르면 열림) | 패널이 열린 동안에는 클릭이 막히므로 오브젝트가 가려져도 된다. 다만 **시안 광원은 두지 않는다** (§1.5) |
| 피드백 문구 | x 660 ~ 1260, y 980 ~ 1060 | 어두운 바닥이어야 흰 글씨가 읽힌다 |

### 4.5 광원과 요미의 조화

- 요미 `T1/Calm`은 **중립 백색광 기준으로 그려져 있고, 새로 그리지 않는다.** 요미 영역 주변 조명은 극단적인 색으로 물들이지 않는다. 시간대별 색감 차이는 요미 뒤 창빛과 방 가장자리에서 주로 표현한다.
- 요미의 바닥 그림자는 코드에서 따로 붙인다. **배경에 요미 그림자를 그리지 않는다.**
- 요미 뒤 창문이 역광을 만들되, 요미 실루엣 가장자리에 밝은 테두리를 그려 넣지 않는다 (요미가 레이어로 따로 올라감).

## 6. 시간대별 조명 지시

## 7. 레이어 제작 규칙

### 7.1 배경 (B1~B4)
- 알파 없음. 1920×1080 전체를 채운다.
- 화면 가장자리 약 40px는 어둡게 물린다(비네팅). 21:9 같은 넓은 화면에서는 위아래가 약간 잘리므로, 위아래 **각 60px 안에는 중요한 요소를 두지 않는다.**

### 7.2 오브젝트 (O1~O4)
- 게임은 **알파 10% 미만 픽셀을 클릭하지 않는 영역**으로 판정한다. 따라서:
  - 오브젝트 밖에 **떠도는 점, 잔여 브러시 자국, 옅은 안개를 남기지 않는다.** 투명해 보여도 알파가 10%를 넘으면 그 자리를 클릭해도 오브젝트가 반응한다.
  - **발광(모니터 빛 번짐), 바닥 그림자, 벽에 비친 빛은 오브젝트 레이어에 넣지 않고 배경에 그린다.** 넣으면 빛 번짐 영역까지 클릭 판정이 넓어진다.
  - 외곽선 안티에일리어싱(1~2px 반투명 테두리)은 허용한다.
- 오브젝트 레이어를 켜고 끄면 **그 자리에 자연스러운 빈 벽·바닥이 드러나야 한다** (배경에 오브젝트 형태의 구멍이나 잔상 없음).
