# 요미의 방 — 상호작용 모달 UI 규격서

> **작성일**: 2026-08-13
> **대상**: UI 제작자 / 아트
> **핵심**: **이미지를 지정된 경로에 넣기만 하면 즉시 반영됩니다.** 씬 편집도, 프리팹 연결도, 코드 수정도 필요 없습니다.
> **관련 문서**: [SaveData_And_YomiHint_Integrated_Plan.md](../P2_04_System/SaveData_And_YomiHint_Integrated_Plan.md) · [P2_05_UI_Asset_Assembly.md](P2_05_UI_Asset_Assembly.md)

## 1. 왜 이런 방식인가

요미의 방 UI는 **씬 파일이나 프리팹이 아니라 런타임에 코드가 조립**합니다
([YomiRoomTopDownPrototypeBuilder.cs](../../Assets/Scripts/DatingSim/UI/YomiRoomTopDownPrototypeBuilder.cs)).

그래서 UI 제작자가 씬을 열 필요가 없습니다. 조립기는 정해진 `Resources` 경로에서 이미지를 찾고,

- **이미지가 있으면** → 그 이미지로 그립니다
- **이미지가 없으면** → 단색 임시 UI로 그대로 동작합니다

즉 **작업 순서에 의존성이 없습니다.** 개발이 먼저 끝나도 임시 UI로 테스트되고, 아트가 나중에 들어와도 코드를 건드리지 않습니다.

## 2. 넣어야 할 이미지 (전부 선택 사항)

경로는 **`Assets/Resources/DatingSim/YomiRoom/UI/Modal/`** 입니다. 파일명은 정확히 지켜 주십시오 (확장자는 `.png`).

| 파일명 | 역할 | 권장 크기 | 9-슬라이스 여백 | 없을 때 |
| --- | --- | --- | --- | --- |
| `Dim.png` | 배경 어둡게 덮는 막 | 아무 크기(늘어남) | — | 검정 60% 반투명 |
| `PanelFrame.png` | 모달 본체 프레임 | 640 × 400 | **32 / 32 / 32 / 32** | 남색 단색 + 외곽선 |
| `ButtonPrimary.png` | 주 행동 버튼 (왼쪽) | 240 × 88 | **24 / 24 / 24 / 24** | 시안(#22D3EE) 단색 |
| `ButtonSecondary.png` | 보조 행동 버튼 (가운데) | 240 × 88 | **24 / 24 / 24 / 24** | 앰버(#FFC45E) 단색 |
| `ButtonCancel.png` | 취소 버튼 (오른쪽) | 240 × 88 | **24 / 24 / 24 / 24** | 핑크(#F472B6) 단색 |

### 9-슬라이스 여백이란

프레임과 버튼은 화면 비율에 따라 **늘어납니다.** 모서리 장식이 찌그러지지 않도록 상하좌우로 "늘리지 않을 여백"을 지정합니다. 위 표의 숫자가 그 값이며, **코드에 이미 박혀 있으니 아트가 따로 설정할 필요는 없습니다.** 다만 이미지를 만들 때 **가장자리 24px(버튼) / 32px(패널) 안쪽에 장식을 두지 마십시오.** 그 영역은 늘어납니다.

```
  ┌──32──┬──────── 늘어남 ────────┬──32──┐
  32     │                        │      32   ← 모서리는 고정
  ├──────┼────────────────────────┼──────┤
  │ 늘어 │       늘어남           │ 늘어 │
  │  남  │                        │  남  │
  ├──────┼────────────────────────┼──────┤
  32     │                        │      32
  └──32──┴────────────────────────┴──32──┘
```

### 픽셀아트 주의

조립기는 모든 UI 텍스처를 `FilterMode.Point`(니어리스트 이웃)로 강제합니다. **픽셀아트 기준으로 그리십시오.** 부드러운 그라데이션은 계단이 보일 수 있습니다.

## 3. 레이아웃 규격

모달은 화면 중앙 **42% × 42%** 영역을 차지합니다(앵커 0.29~0.71). 내부 배치는 패널 기준 비율입니다.

```
┌─────────────────────────────────────────────┐  ← PanelFrame.png
│                                             │
│   침대                              (0.7~0.9 세로)
│   ─────────────────────────────             │  ← Title (30pt, 시안)
│                                             │
│   잠깐 눈만 붙일까, 오늘은 여기까지 할까?      │  ← Body (21pt, 밝은 회색)
│                                             │     (0.38~0.7 세로)
│   눈 붙이기: 체력 +10 / 슬롯 -1              │
│   취침: 하루 마감                            │
│                                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐    │
│  │잠깐 눈   │ │오늘은    │ │  취소    │    │  ← 버튼 3개 (0.09~0.29 세로)
│  │붙이기    │ │여기까지  │ │          │    │
│  └──────────┘ └──────────┘ └──────────┘    │
│   Primary      Secondary     Cancel         │
│   0.07~0.35    0.37~0.65     0.67~0.95      │
└─────────────────────────────────────────────┘
```

| 요소 | 앵커 (min → max) | 비고 |
| --- | --- | --- |
| 패널 | `0.29,0.29` → `0.71,0.71` | 화면 기준 |
| 제목 | `0.08,0.7` → `0.92,0.9` | 30pt Bold, `#22D3EE` |
| 본문 | `0.08,0.38` → `0.92,0.7` | 21pt, `#E2EBF3` |
| 주 버튼 | `0.07,0.09` → `0.35,0.29` | 패널 기준 |
| 보조 버튼 | `0.37,0.09` → `0.65,0.29` | **상황에 따라 숨겨짐** |
| 취소 버튼 | `0.67,0.09` → `0.95,0.29` | 위치 고정 |

> **보조 버튼이 꺼져도 나머지 두 버튼은 움직이지 않습니다.** 가운데가 비는 배치가 되므로, 그 상태에서도 어색하지 않은 디자인이어야 합니다. (버튼을 채워 넣는 레이아웃 재계산은 의도적으로 하지 않습니다 — 위치가 매번 바뀌면 오조작이 늘어납니다)

## 4. 버튼 3개의 의미

| 버튼 | 색 역할 | 성격 |
| --- | --- | --- |
| **주 행동** (Primary) | 시안 계열 | 가장 흔하고 되돌릴 수 있는 행동 |
| **보조 행동** (Secondary) | 앰버 계열 | **되돌릴 수 없는 행동.** 하루가 끝나는 등 상태가 크게 바뀜 |
| **취소** (Cancel) | 핑크 계열 | 아무 일도 일어나지 않음 |

**보조 버튼은 시각적으로 "무겁게"** 보여야 합니다. 취침은 하루를 끝내는 결정이라, 눈 붙이기와 같은 무게로 보이면 오조작이 납니다.

### 상호작용별 버튼 구성

| 상호작용 | 주 행동 | 보조 행동 | 취소 |
| --- | --- | --- | --- |
| **침대** | "잠깐 눈 붙이기" (체력 +10 / 슬롯 -1) | **"오늘은 여기까지"** (취침 → 다음 날) | 있음 |
| **PC** | "확인" (거래 개시) | 없음 (숨김) | 있음 |

주 버튼은 **조건을 만족하지 못하면 비활성**됩니다 (예: 슬롯이 0이면 눈 붙이기 불가). 비활성 상태의 시각 표현도 함께 준비해 주십시오 — Unity `Button`의 기본 `Disabled` 컬러 틴트가 적용됩니다.

## 5. 문구는 코드가 넣습니다

버튼 라벨과 본문은 **상호작용 종류에 따라 런타임에 바뀝니다.** 이미지에 글자를 그려 넣지 마십시오.

문구 정의 위치는 [YomiRoomTopDownPrototype.cs](../../Assets/Scripts/DatingSim/YomiRoom/YomiRoomTopDownPrototype.cs)의 `PrimaryLabelFor()` / `SecondaryLabelFor()` 입니다.

> ⚠️ 한글 문구를 새로 추가하면 **폰트 아틀라스 재생성이 필요합니다.** 메뉴 `Tools/Prebake All Scripts Text into Font` 를 실행하십시오. 실행하지 않으면 글자가 □로 보입니다.

## 6. 확인 방법

1. Unity에서 `Assets/Scenes/YomiRoomScene.unity` 를 열고 **플레이**
2. 방 안에서 캐릭터를 **침대 쪽으로 이동** → 상호작용 프롬프트가 뜨면 상호작용 키
3. 모달에 **버튼 3개**가 보이면 정상
4. PC 쪽으로 가서 상호작용 → **버튼 2개**(주/취소)만 보이면 정상

이미지를 넣기 전이라도 단색 임시 UI로 위 흐름이 전부 동작합니다. 이미지를 넣은 뒤에는 **Unity가 `Resources` 폴더를 다시 임포트한 다음** 플레이하면 즉시 반영됩니다.

---

## 7. 새 상호작용을 추가할 때 (개발자용)

1. `YomiRoomInteractionType` 에 값 추가
2. `YomiRoomTopDownPrototypeBuilder.CreateInteractable(...)` 한 줄로 방에 배치
3. `PrimaryLabelFor` / `SecondaryLabelFor` / `HasSecondaryAction` / `CanExecutePrimary` 에 분기 추가
4. `ConfirmInteraction` / `SecondaryInteraction` 에 실제 동작 연결

UI 조립이나 이미지 작업은 필요 없습니다. 모달은 하나를 재사용합니다.
