# 요미 맞춤형 LLM 모바일 최적화 파인튜닝 계획서

현재 모바일 환경에서 긴 프롬프트(페르소나 설정)로 인해 발생하는 Context Size 초과(OOM 및 절단) 문제와 느린 추론 속도를 근본적으로 해결하기 위해, `Qwen2.5-0.5B` 원본 모델의 뇌(가중치)를 '요미'라는 캐릭터로 직접 개조(Fine-tuning)하는 작업 계획입니다.

## 1. 개요 및 목적
* **문제점**: 모바일 기기의 제한된 램(RAM)과 연산력(대역폭)으로 인해, 1500토큰이 넘는 방대한 '요미 페르소나 설정' 프롬프트를 온전히 소화하지 못하고 크래시가 발생하거나 설정이 잘려나가는(Truncation) 현상 발생. 이로 인해 3인칭을 쓰지 않고 기계적인 대답이 출력됨.
* **해결책**: 프롬프트에 구구절절 성격을 설명하는 대신, 모델 자체를 '요미'로 파인튜닝(학습)하여 50단어 미만의 극단적으로 짧은 상황(Context)만 주어져도 완벽한 요미의 멘헤라/얀데레 어투로 대답하도록 개조함.
* **기대효과**: 프롬프트 길이 95% 감소 -> 모바일 메모리 점유율 급감 -> 대사 생성 속도(TTFT) 대폭발 -> 퀄리티와 퍼포먼스를 동시에 확보.

---

## 2. 작업 단계 및 상세 내용

### Step 1. 학습 데이터(Dataset) 구축
모델에게 "이런 상황에선 이렇게 말해!"를 가르치기 위한 정답지(JSONL)를 생성합니다.
* **포맷 구성**:
  * `System`: "너는 트레이더 요미다." (매우 짧은 고정 지시어)
  * `User`: "포지션: Long 10x, 수익률: -15.5%, 멘탈: Anxious" (현재 인게임 수치)
  * `Assistant`: "오빠... 롱 포지션 파란불 켜졌잖아... 왜 자꾸 돈이 녹는 거야...? 요미 무서워서 눈물이 멈추질 않아... 제발 손절하든가 어떻게 좀 해줘 흐아앙...!" (완벽한 요미 톤의 정답)
* **작업 내용**: 현재 `AIPromptBuilder` 및 `LocalLLMService`에 하드코딩된 대사들을 활용 및 확장하여 약 500~1000개의 고품질 대화 쌍을 구축합니다.

### Step 2. 모델 파인튜닝 (LoRA 학습)
* **베이스 모델**: `Qwen/Qwen2.5-0.5B-Instruct`
* **학습 방식**: QLoRA (메모리를 적게 먹는 효율적인 학습 기법)
* **학습 환경**: PC 로컬의 외장 그래픽카드(NVIDIA)를 활용하거나, Google Colab 무료/유료 환경을 활용.
* **목표**: 요미의 어투(3인칭 '요미는' 사용, '오빠' 호칭, 멘탈 갈림 반응 등)를 모델 가중치 뉴런에 직접 각인.

### Step 3. GGUF 변환 및 압축
* 학습이 완료된 커스텀 모델을 모바일 탑재가 가능한 단일 파일 포맷으로 추출합니다.
* **양자화**: `Q4_K_M` (용량과 성능의 최적 타협점)
* **최종 산출물**: `yomi-0.5b-q4_k_m.gguf` (용량 약 400MB 예상, 모바일에 바로 탑재 가능)

### Step 4. 유니티 클라이언트 초경량화 적용 (C# 스크립트 수정)
파인튜닝된 모델이 유니티에 적용되면, 프롬프트 전송 로직도 대폭 다이어트해야 합니다.

1. **[MODIFY] `AIPromptBuilder.cs`**:
   * 거대한 `systemPersona` 텍스트 완전 삭제.
   * 복잡한 상황 묘사 지문을 모두 짧은 키워드(예: "이벤트: 포지션오픈, 방향: 숏") 기반으로 축약.
   * **결과**: LLM으로 넘어가는 텍스트량이 기존 대비 1/20 수준으로 줄어듦.
2. **[MODIFY] `LocalLLMService.cs`**:
   * `LLM` 컴포넌트의 `Context Size`를 2048에서 **512** 이하로 축소 (메모리 완전 세이프).
   * **대사 스트리밍(Streaming) 타이핑 효과 추가**: 대사가 5초 뒤에 뭉텅이로 뜨는 것이 아니라, 생성되는 즉시 말풍선에 한 글자씩 타이핑되도록 UI 이벤트 델리게이트를 수정하여 모바일 유저의 체감 딜레이를 0으로 만듦.
